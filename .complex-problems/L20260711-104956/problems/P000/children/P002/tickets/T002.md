# 实现分页 reducer 与本地图谱 CAS

## Problem Definition

iOS change consumer 解析与副作用耦合，无法验证多页链；KBLite export 与 apply 之间本地写入可能被覆盖。

## Proposed Solution

在知识同步模型中加入严格 typed page/reducer，只保留最终 graph/revision；KBLiteManager 增加 mutation version snapshot 与 expected-version CAS apply，所有 save/user switch 推进版本。补纯模型和源码/构建验证。

## Acceptance Criteria

- Reducer 验证稳定 target、strict contiguous revisions、hasMore/next、空页、legacy 和最大页数。
- 中间页无 store 副作用且只保留最后 graph。
- KBLite snapshot 原子返回 dictionary/version/user；CAS stale 不修改 graph。
- 本地写入后重算 merge 可保留本地知识。
- model smoke 和 iOS build 通过。

## Verification Plan

新增 Swift model smoke 覆盖正常三页、legacy、异常页和 CAS policy；运行 workspace build 与现有 three-way merge/governance gates。

## Risks

- graph mutation version 必须覆盖 save 和 user switch。
- CAS 失败不能与 invalid graph 混淆。
- 不应改变现有 public KBLite API 行为。

## Assumptions

- 每个 change 当前包含完整 graph，revision 连续。
