# Coordinator 分页集成交付验收

## 判定

成功。

## 验收依据

- 分页读取使用固定 target，typed page 与 reducer 对身份、水位、连续 revision、终页和页数上限进行严格验证。
- Coordinator 的中间页没有 remote base、pending、KBLite 或 mutation 副作用；终页才执行合并与后续 push。
- 正常 pull 与 409 refresh 共用状态机，旧用户、旧 generation 和旧 pull session 回调被拒绝。
- KBLite CAS 在终页提交前检测本地 graph 变化并有限重算，满足分页期间新知识不被覆盖的核心要求。
- 模型 smoke、Coordinator 检查、跨仓 gate、254 个后端测试、Simulator/generic iPhoneOS build 和 release regression 均通过。
- 生产后端已部署，真实 Postgres smoke 证明 target 固定后新增 revision 不进入当前分页轮次。
- legacy 客户端和旧后端单页合同均保留兼容，没有公开 UI 变化。

## 剩余风险判断

保留/compaction、snapshot fallback 和中间页恢复 journal 已明确列为非目标，不影响本任务成功。真机不属于该数据合同任务的验收条件。
