# 集成分页同步状态机并完成交付

## Problem Definition

Client 仍返回 raw object，Coordinator 正常/冲突刷新各执行一次性 fetch/apply/push，无法使用 reducer 或 CAS，也没有分页组合门禁。

## Proposed Solution

Client 使用 URLComponents 构造分页 query 并返回 typed page；Coordinator 增加 pullSessionID 和递归 reducer，正常/409 refresh 共用 begin/pull/terminal commit。终页通过 CAS 有界重算后 apply 一次，再 push；中间页无副作用。接入 QA/release/docs 并全量验证提交。

## Acceptance Criteria

- 每页绑定 user/generation/pull session，旧回调丢弃。
- target 首次固定并传给后续请求。
- 终页前不调用 apply/push/governance drain。
- CAS stale 最多重算三次，失败不推进 base/pending。
- legacy response 单页兼容，malformed 不 fallback v1。
- 跨仓 gate、release regression、两类 build 通过并分仓提交。

## Verification Plan

运行 pagination model/client/coordinator checks、backend delta smoke、knowledge governance/V2 gates、release regression、Simulator 与 generic iPhoneOS build。

## Risks

- finishSync 必须清 active pull，避免旧页复活。
- 409 refresh 只能重试 local mutation 一次。
- 空 revision 0 终页需构造安全空远端 graph。

## Assumptions

- 后端新合同已由 P001 完成，旧后端仍返回 legacy 单页。
