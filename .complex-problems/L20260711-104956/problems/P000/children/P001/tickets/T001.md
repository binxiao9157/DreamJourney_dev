# 实现后端稳定水位分页

## Problem Definition

知识 change feed 无界返回，无法固定一次同步读取的目标 revision；连续写入下客户端无法安全分页。

## Proposed Solution

为 store 增加可选 through revision/limit bounded query；API 在显式 limit 时固定或校验 targetRevision，返回 nextSinceRevision/hasMore/pageLimit，legacy 无 limit 响应保持不变。补 Memory/Postgres/API 和 deterministic smoke。

## Acceptance Criteria

- limit 1...100，target/since 非负且 since<=target<=current。
- 多页严格升序，target 后新增 change 不进入本轮。
- hasMore/next 水位一致，空终页安全。
- legacy 调用及现有测试不变。
- 后端全量验证通过。

## Verification Plan

运行 core/Postgres 分页测试、分页 API smoke、全部 backend verify 和 diff check。

## Risks

- FakeCursor 必须支持 upper-bound 与 limit SQL。
- currentRevision/targetRevision 语义不能破坏旧 iOS。
- 并发写入后续 revision 必须留给下一轮。

## Assumptions

- 每 revision 对应一条 change，且 revision 连续。
