# 落地知识证据与 Persona-bound Context P0 门禁

## Problem Definition

当前 KBLite、后端 `/kb/extract` 与 Echo Context 已经具备同步和检索能力，但证据和身份边界仍不完整：iOS 把 user/assistant 作为一段文本上送，后端不验证 provider 返回的来源 turn；低置信 fact 可进入生成；family persona 请求失败会回退 viewer 私有 KBLite；Context 响应也未完整绑定当前 user/persona/digital-human gate。上述问题可能把 AI 回复或错误角色数据注入后续 Echo。

## Proposed Solution

以 additive 兼容方式增加 extraction v2 structured turns 与 `userEvidenceOnly` policy，后端对 role/index/长度进行校验并在 provider 后处理阶段只保留至少引用一个有效 user turn 的实体，响应只返回不含正文的 evidence summary。后端 Context 与 iOS 本地 fallback 统一只允许 high/confirmed fact。iOS 增加后端精提取独立水位，发送 indexed turns，并把本地 fallback 限制为 personal/self；family persona 失败返回空知识上下文。Context Packet 在提交 SDK 前验证 user/persona/digital-human identity。补齐时间信件收件人和 care viewer 的负向测试，接入现有 release regression。

## Acceptance Criteria

- assistant-only、无来源、越界来源和只引用 assistant turn 的实体不会被接受。
- `/kb/extract` v1 transcript 保持兼容，v2 返回无原文 `evidencePolicy` 摘要。
- low/medium fact 可以存储，但不会进入后端或 iOS 本地 generation context。
- 后端精提取节流不再被每轮本地 fallback 的总 sessionCount 永久推迟。
- family persona 超时/失败不会读取 viewer 私有 KBLite。
- user/persona/digital-human identity 不匹配的 Context Packet 不会提交生成。
- 时间信件非收件人、未到期、无效 family/care viewer 不进入 Context。
- Task 12/13 mutation、tombstone、三方合并、旧合同与公开 release regression 不退化。

## Verification Plan

后端运行全量 unittest、FastAPI smoke、knowledge v1/v2、Context V2 和新增 evidence policy smoke；iOS 运行 structured extraction/persona policy model smoke、knowledge static guard、三方合并模型、release regression、generic Simulator 和 generic iPhoneOS Debug build；两个仓库运行 `git diff --check`。不执行真机测试。

## Risks

- 旧 provider 结果可能缺少 sourceTurnIndices；v2 应安全过滤并让 iOS 本地规则降级，不能放宽证据要求。
- family persona 禁止本地 fallback 后，后端不可用时上下文会减少；这是明确的隐私优先取舍。
- 新的 Context identity 字段可能在旧后端缺失；personal/self 兼容要以当前 request gate 为边界，family 不能 fail-open。
- 不能在本任务顺带重写全局 Postgres 连接模型或公开 UI。

## Assumptions

- 当前 `/kb/mutations` V2、revision/change feed 与 Context V2 schema 保持兼容。
- `generationAllowed` 表示可以离开设备，但不等于对所有 persona 或 family viewer 都可见。
- 本轮不引入向量数据库，不做真实 provider/真机验收。
