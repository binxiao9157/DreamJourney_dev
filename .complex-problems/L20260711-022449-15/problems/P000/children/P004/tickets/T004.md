# 固化 Task 14 跨仓库交付门

## Problem Definition

新 policy 必须进入日常 QA 和状态文档，否则后续改动会绕过。

## Proposed Solution

把后端 evidence/context smoke 纳入 verify_backend，把 iOS policy smoke/static guard 纳入 release regression，更新 canonical/状态/Task 文档，运行非真机验证并分别提交。

## Acceptance Criteria

- 所有新增/既有知识 gate、后端全量测试和 generic builds 通过。
- 报告可定位证据过滤和 persona fallback，不包含正文。
- 两仓库 diff 可审阅并分别提交，不推送部署。

## Verification Plan

执行任务文档列出的完整命令，保留 release regression report 路径并做 `git diff --check`。

## Risks

- release regression 运行时间增加；新增 gate 应保持本地、确定性、无需外部 key。

## Assumptions

- 真机和线上部署不属于本任务验收条件。
