# Task 6 根问题成功验收

## Summary

验收通过。当前实现已在既定非真机范围内消除哈希选槽导致的跨用户覆盖风险，建立逻辑音色档案与供应商音色槽的持久化独占关系，并在合成前完成归属与可用状态校验。账号最终清理也会退役已绑定槽位，不会把残留声音重新分配给其他用户。

## Evidence

- 内存与 Postgres 存储均实现独占分配、同档案重试复用、容量耗尽、状态更新与永久退役合同。
- Postgres 分配使用唯一约束和 `FOR UPDATE SKIP LOCKED`，并通过并发合同测试。
- 后端训练、状态刷新和合成只在内部使用 `providerSpeakerId`；公开 API 与 iOS 继续使用逻辑 `voiceProfileId`。
- `/voice/synthesis` 校验用户归属、ready、enabled、供应商就绪、质量验收和 provider binding。
- iOS 新档案采用 `vp_` 逻辑 ID，并能解析 provider binding 状态；已有 `S_` 档案保留兼容路径。
- `verify_backend.sh` 通过 141 项测试、编译检查、声音复刻合同 smoke、FastAPI smoke 和 diff 检查。
- 10 个相关 Swift QA guard 与 iOS Debug 模拟器通用构建通过。

## Criteria Map

- 同一供应商音色槽不能被两个逻辑档案拥有：由存储唯一绑定、原子分配及内存/Postgres 测试证明。
- 三槽池的第四个活跃档案明确失败：后端返回 HTTP 409，测试覆盖容量耗尽，不会覆盖已有声音。
- 非法合成被拒绝：缺失、跨用户、禁用、删除、未 ready 或未质量验收均有 404/409 合同测试。
- 有效逻辑档案可解析供应商槽：训练、refresh、synthesis 均通过内部 binding 调用 provider。
- 旧 `S_` 档案兼容：legacy direct provider 路径和测试已保留。
- iOS 无需供应商槽 ID：角色、家人和 Echo 合同只依赖逻辑 `voiceProfileId`，静态 guard 通过。
- 后端与 iOS 非真机验证通过：完整后端验证、QA guard 和模拟器构建均成功。

## Stress Test

- 两个用户分别占用不同槽位，同档案重试保持原槽，容量耗尽后新档案无法分配。
- 档案删除或账号最终清理后槽位进入 `retired`，新用户无法继承该槽位。
- 跨用户复用同一逻辑档案 ID 和跨用户合成均被拒绝。

## Residual Risk

- 服务器尚未部署新表和合同，部署后必须在真实 Postgres 上运行 deployed smoke；这属于当前非部署任务之外的外部验收。
- 三个试用槽只支持三个未退休档案，扩容依赖购买或配置新的供应商槽位。
- 真机听感、腾讯 audio-drive 和麦克风恢复不属于本任务范围，仍需后续真机阶段验收。
