# 将独占槽接入声音复刻全生命周期

## Problem Definition

API 仍直接把客户端逻辑 ID 当成 provider speaker，且 synthesis 没有 profile 授权校验，无法利用刚实现的独占槽边界。

## Proposed Solution

抽取 pool-mode/configured-speaker helper。创建 profile 时在 pool 模式原子分配槽，以逻辑 ID 保存 profile、以 `providerSpeakerId` 调 provider；refresh 和 synthesis 从持久化 profile 解析 provider ID。增加公开 profile 过滤，响应只暴露 binding mode/state，不暴露真实 provider ID。生命周期操作同步槽状态，删除退休。synthesis 强制验证归属、ready、enabled、quality accepted 和 provider readiness，并保留旧 `S_` profile fallback。

## Acceptance Criteria

- pool 模式第四个 profile 对三槽配置返回 409。
- profile API 返回逻辑 ID，不把真实 provider ID暴露给 iOS。
- provider 收到分配后的真实 `S_` ID。
- refresh、synthesis、disable、delete 更新正确槽状态。
- synthesis 拒绝未持久化、跨用户和未验收 profile。
- legacy `S_` profile 仍能合成。
- API、provider 与 runtime 测试通过。

## Verification Plan

先增加 FastAPI 失败测试和 provider 参数断言，再修改 service/main/runtime。运行 `tests.test_core_services` 和完整后端验证。

## Risks

- 当前测试中部分 synthesis 直接传 `S_` 而没有 seed profile，需要改成显式 legacy profile fixture。
- provider 返回的 speaker ID 不能覆盖逻辑 ID。

## Assumptions

- 旧 `S_` profile 只有在后端已持久化且状态可用时兼容。
- provider speaker ID 仅在后端内部存储和日志中使用。
