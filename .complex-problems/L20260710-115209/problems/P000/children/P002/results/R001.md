# 音色逻辑 ID 与 provider ID 分离合同已接入

## Summary

训练、refresh 和 synthesis 已统一通过持久化 profile 解析 provider speaker；公开 API 保留逻辑 `voiceProfileId` 并隐藏真实 `providerSpeakerId`。合成新增所有权、状态、启用和质量验收校验。

## Done

- 删除 provider 层哈希选槽，pool 模式只接受已分配的 configured speaker。
- 创建 profile 时分配独占槽，容量耗尽返回 HTTP 409。
- provider 返回的 `S_` ID 不再覆盖逻辑 profile ID。
- refresh 使用绑定的 provider ID；disable/delete 同步 slot，删除进入 retired。
- synthesis 验证持久化归属、ready、enabled、provider ready 和 quality acceptance。
- legacy `voiceProfileId=S_...` profile 保留直接解析兼容。
- profile 响应隐藏 `providerSpeakerId`，暴露 binding mode/state。
- 防止相同逻辑 profile ID 被另一用户覆盖。
- runtime 合同升级到 v2，声明 exclusivePersistentSlot 和 retireOnDelete。
