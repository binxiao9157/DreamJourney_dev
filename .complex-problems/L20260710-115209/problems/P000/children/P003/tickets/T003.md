# 收敛 iOS 逻辑 ID、deployed smoke 与交接文档

## Problem Definition

iOS 新建 profile 仍使用 `S_` 前缀，deployed smoke 依赖“任意用户直接合成并先删除 profile”的旧宽松合同，文档也把真实 provider 槽和产品 profile 混为一谈。

## Proposed Solution

将 iOS 新逻辑 ID 改为 `vp_`，在 client/snapshot 中解析 binding mode/state。重写 deployed smoke：明确 profile owner、读取/refresh 已持久化 profile、必要时质量确认、先合成后结束且绝不删除真实 profile。扩展静态 guard，更新 runtime/部署/实现文档与 Lodestar 状态。

## Acceptance Criteria

- 新建 iOS profile 使用 `vp_`，旧 `S_` 本地 profile 正常读取。
- iOS 可解析 `providerBindingMode/providerSlotState/providerSlotManaged`。
- deployed smoke 不创建或删除真实 ready profile，且按 owner 调 synthesis。
- 静态 guard 阻止真实槽默认值、哈希分配语义和先删除后合成回归。
- 文档明确逻辑 ID、独占槽、retire-on-delete、容量和部署迁移。
- iOS build、Swift QA、后端验证及 diff check 通过。

## Verification Plan

运行 backend smoke static check、相关 voice clone Swift checks、release QA package check、iOS Debug simulator build、后端 verify 和两个仓库 diff check。

## Risks

- 已部署 profile 的 owner user ID 必须由 QA 明确提供，不能继续使用随机 probe user。
- 不应在 smoke 中破坏或删除真实已训练音色。

## Assumptions

- deployed smoke 的 `VOICE_CLONE_READY_PROFILE_ID` 指逻辑 profile ID；legacy 环境中它可以仍是 `S_`。
- 真机听感不在本任务范围。
