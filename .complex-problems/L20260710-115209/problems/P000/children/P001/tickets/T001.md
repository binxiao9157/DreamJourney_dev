# 为内存与 Postgres 增加独占音色槽存储

## Problem Definition

后端没有 provider speaker 的持久化所有权，无法安全支持多个本人/家人音色 profile。

## Proposed Solution

新增 `voice_clone_slots` 表和 store API。配置槽先幂等注册；分配使用单条 Postgres CTE + `FOR UPDATE SKIP LOCKED` 选择已有绑定或可用槽，并原子更新为 assigned。内存 store 实现相同行为。提供状态更新、查询和列表能力，删除后标记 retired。

## Acceptance Criteria

- schema 包含 provider speaker 主键和唯一逻辑 profile 绑定。
- 同一逻辑 profile 重复分配返回同一槽。
- 不同 profile 不会获得同一槽。
- 满容量返回 `None`。
- retired 槽不再分配。
- Postgres fake/store 测试覆盖并发竞争模拟。

## Verification Plan

先扩展 `tests/test_postgres_store.py` 和独立内存 store 测试，再实现 schema 和方法，运行相关 unittest。

## Risks

- FakeCursor 必须准确模拟 CTE 分配，否则测试可能只验证假实现。
- 老数据库需要通过 `CREATE TABLE IF NOT EXISTS` 无损升级。

## Assumptions

- provider speaker 配置列表由环境变量提供。
- 槽删除后默认退休，不自动清空 provider 数据。
