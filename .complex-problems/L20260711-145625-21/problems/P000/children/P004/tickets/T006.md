# 固化 Widget 隐私发布门并收口 Task 21 证据

## Problem Definition

当前三个模型 runner 尚未接入默认 release regression，工程/entitlement/生命周期也没有静态防回归检查；Task 21 文档仍是未完成清单，后续修改可能重新引入跨账号或正文泄露。

## Proposed Solution

新增单一 Widget privacy lifecycle 静态 gate，解析关键源码、entitlements 和 pbxproj 合同；将三个模型 runner 与静态 gate 作为默认步骤接入 `run-release-regression.sh` 和 release QA package 检查清单。运行全部相关检查、release regression 和最终构建，更新计划/状态/覆盖矩阵与 Closure 证据，删除临时票据文件后提交推送。

## Acceptance Criteria

- 静态 gate 会阻止默认授权、description/raw ID 共享、缺 owner/generation/reload、provider 不校验、entitlement/bundle/dependency/embed 漂移。
- 三个模型 smoke 和静态 gate 默认出现在 release regression，不需环境开关。
- release QA package 能确认 runner 可执行且 release script 已包含步骤。
- 全部 smoke、git diff check、release regression、Simulator/generic iPhoneOS build 通过。
- Task 21 文档验收项、状态索引、PRD 覆盖与 progress 更新为有证据的完成态，同时明确真机外部门槛。

## Verification Plan

先写静态脚本并故意确认其检查当前合同，再接 release runner；运行相关 smoke、release QA package、完整 release regression 和最终两类构建。使用 Closure check/validate 确认账本关闭后再提交推送。

## Risks

- 完整 release regression 时间较长，失败时需区分 Task 21 回归与既有可选后端环境门。

## Assumptions

- 现有 release regression 默认不会要求真机或可选线上后端开关。
