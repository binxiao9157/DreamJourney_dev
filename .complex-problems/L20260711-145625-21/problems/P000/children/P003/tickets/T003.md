# 让 Widget fail closed 并作为主 App 扩展正确交付

## Problem Definition

Widget 仍读取无身份旧 schema 并展示 description，且 Xcode 工程没有把扩展嵌入主 App、没有 target dependency、双方没有一致 App Group entitlement，Bundle ID 也不满足随主 App 派生的交付合同。

## Proposed Solution

将 Widget 共享模型升级为与主 App schema v2 对齐的最小结构，Provider 从可配置 App Group 读取 shared active owner digest 并校验 schema/owner 后才生成 entry，任何异常为空态；View 删除 description 并标记事件摘要为 privacy sensitive。新增 Widget entitlements，更新主 entitlements、Info.plist 与 build settings；在 pbxproj 中加入新生产文件、Embed App Extensions copy phase、target dependency，并让 Widget bundle/team/app-group 从主设置派生。

## Acceptance Criteria

- Widget 读取端拒绝旧 schema、身份不匹配、缺失 active owner 和损坏 JSON。
- UI 不展示 description；placeholder 不冒充真实家庭数据；知识摘要使用系统隐私标记。
- 主 App target 编译新策略/存储文件并嵌入 `DreamJourneyWidget.appex`。
- Widget product bundle ID 为 `$(DREAMJOURNEY_PRODUCT_BUNDLE_IDENTIFIER).widget`，team 与主 App 共用，双方 entitlements 使用同一 `$(DREAMJOURNEY_APP_GROUP_IDENTIFIER)`。
- 模拟器和 generic iPhoneOS 构建通过，构建产物含 `.appex`；不宣称已完成 Developer Portal/provisioning 真机验收。

## Verification Plan

先增加 Widget provider 纯读取 smoke/静态检查，再修改 shared models/provider/view 和工程文件。用 `xcodebuild -showBuildSettings`、Simulator build、generic iPhoneOS build 和产物检查验证 target 配置与扩展嵌入；运行 `plutil` 检查 entitlements/Info.plist。

## Risks

- 手工编辑 pbxproj 容易产生引用或 copy phase 错误，必须通过两种 SDK 构建和产物检查验证。
- App Group capability 是否已在 Apple Developer Portal 注册无法从非真机构建完全证明。

## Assumptions

- 主 App 本地 bundle/team build settings 是仓库既有覆盖入口，Widget 应派生而不是新增第二套本机配置。
- 公开产品尚无 Widget 内容授权 UI，因此大多数真实快照仍为空是预期的安全行为。
