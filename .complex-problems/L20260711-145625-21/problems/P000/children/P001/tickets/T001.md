# 实现纯 Swift Widget 隐私投影合同

## Problem Definition

Widget 共享数据目前没有独立披露授权或最小字段 schema，无法用自动化测试证明 legacy、其他账号、其他 persona 或低置信证据不会进入系统表面。

## Proposed Solution

扩展 `KBPrivacyMetadata`，以可选 `widgetVisibility` 表示显式摘要授权；新增 Foundation/CryptoKit 纯模型 `KnowledgeWidgetPrivacyPolicy`、schema v2 snapshot 和摘要事件，集中完成 allowlist、不可逆摘要标识、标题规范化及最小投影。先编写独立 Swift smoke，直接编译相关模型与策略，覆盖允许和拒绝组合。

## Acceptance Criteria

- 解码旧知识数据时 `widgetVisibility` 缺失不会失败且默认拒绝。
- 只有 scope、widgetVisibility、owner、persona、evidence 五项全部符合才生成摘要。
- 摘要无 raw owner/event/source ID、description 和 sourceRefs。
- owner/event digest 使用稳定不可逆 SHA-256，标题有确定长度上限与空白规范化。
- 独立模型 smoke 通过并对每个拒绝维度提供断言。

## Verification Plan

新增并运行 `knowledge-widget-privacy-policy-model-smoke.swift`；检查编码 JSON 中禁止字段和原始 ID 不存在；运行 `git diff --check`。本票据不要求 App Group IO、WidgetKit 或工程构建。

## Risks

- CryptoKit 在脚本编译环境中的模块可用性需验证。
- 新可选字段必须保持现有 Codable 数据兼容，不能要求历史数据迁移。

## Assumptions

- `summaryAllowed` 由后续显式产品/QA 流程设置，本轮所有旧数据保持 deny。
- 标题是唯一允许进入 Widget 的知识文本字段，description 一律禁止。
