# 建立可撤销且防旧写覆盖的 Widget 快照存储

## Problem Definition

当前共享文件写入没有当前账号身份、generation 或 timeline 失效语义。账号切换与保存操作异步交错时，旧用户快照可能最后落盘；登出即使写空图谱，也不能保证已缓存 Widget 立即清空。

## Proposed Solution

新增 `KnowledgeWidgetSnapshotStore`，在串行队列中保存 active owner digest 与 generation，并把 active owner digest 写入 App Group defaults。`activate` 先撤销旧快照；`publish` 只接受当前 owner/generation 并调用纯策略生成快照；`clear` 先移除 active owner 再删除文件。所有状态变化触发 Widget timeline reload，写入使用原子文件和首次解锁后保护。`KBLiteManager` 初始化、保存、切换账号改用该 store，彻底删除旧 `writeToAppGroup`。

## Acceptance Criteria

- store 能用可注入容器/重载器进行非真机模型测试。
- 旧 generation/owner publish 被拒绝且不会重建已清除文件。
- 登录切换先失效旧状态，再发布新快照；登出不写“匿名空图谱”，而是撤销身份并删除文件。
- App Group 不可用、编码或写入失败时 active owner 被撤销/快照被清理，保持 fail closed。
- 成功发布、撤销和失败清理都会请求刷新 `TodayInHistoryWidget`。
- `KBLiteManager` 不再包含旧无条件 event title/description 导出。

## Verification Plan

新增 store 模型 smoke，使用临时目录、内存 active-owner store 和 spy reloader 验证发布、切换、登出、旧 generation、损坏/失败清理；运行现有 KBLite 相关 smoke 与 `git diff --check`。后续 P003 再验证真实 App Group entitlement 和 WidgetKit target。

## Risks

- `KBLiteManager.save()` 的异步队列与内部锁不能在 store 内形成反向锁顺序。
- WidgetKit 不应污染纯测试，因此 timeline reload 需以小协议/闭包注入并在生产 adapter 中调用。

## Assumptions

- 单进程内 `userGeneration` 单调递增，足以阻止切换前延迟写。
- App Group defaults 和文件位于同一共享容器；Widget 读取时会在 P003 同时校验两者。
