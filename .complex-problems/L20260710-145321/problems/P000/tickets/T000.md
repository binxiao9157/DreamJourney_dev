# 建立数字人 Session Lease 与并发控制闭环

## Problem Definition

当前后端数字人 session 是无状态合同：每次请求生成新 ID，缺少持久化、幂等复用、并发仲裁、heartbeat、release 和 TTL。iOS 本地关闭 runtime 后无法同步服务端状态，旧异步成功响应也可能留下无人消费的 session。多设备场景只能等腾讯 SDK 报配额错误，无法提前给出可恢复的冲突合同。

## Proposed Solution

在后端新增不含腾讯凭据的安全 lease 模型，由内存和 Postgres store 负责原子 acquire、同设备复用/替换、容量冲突、heartbeat、release 与过期回收。将 `/digital-human/sessions` 升级到 v2，并新增 heartbeat/release 路由及 runtime capability。iOS 扩展 session contract 和 backend client，在当前 generation 绑定 heartbeat，在页面退出、角色切换、后台宽限到期、provider 终止及旧响应丢弃时释放 lease；用户只停止当前对话时保留 lease。最后增加后端、Postgres、iOS 和模拟器组合 gate。

## Acceptance Criteria

- 同一用户、设备和 context 重复 acquire 返回相同 session，`reused=true`。
- 同设备切角色替换旧 lease；其他设备超过容量时返回结构化 409 与 retry delay。
- heartbeat 只延长当前 owner 的 active lease；release 幂等；TTL 可释放崩溃残留容量。
- Postgres acquire 使用数据库级锁，不能依赖单进程内存锁。
- lease 存储不包含 appkey、accesstoken 或其他腾讯凭据。
- iOS 旧 session 成功响应会主动 release；当前 session 定时 heartbeat。
- stop conversation 不 release；page/context/background/provider terminal 路径 release。
- 后端验证、Postgres store tests、iOS guard、模拟器 smoke、构建与 diff check 通过。

## Verification Plan

先写 API/store 与 iOS 静态失败测试；实现后运行后端完整测试和 FastAPI smoke、Postgres fake/真实可用 smoke、session lease API smoke、iOS release regression、runtime stub/lifecycle 模拟器 smoke、Debug build 和 `git diff --check`。不运行真机。

## Risks

- 后端逻辑 release 不能替代腾讯 SDK `close()`；真实 provider 配额释放时延仍需真机/线上观测。
- App 被系统杀死时无法主动 release，必须依靠 TTL。
- 多 worker Postgres 并发必须使用事务级 advisory lock 或同等数据库原子策略。

## Assumptions

- 当前腾讯资产默认并发配置为 1，但后端字段允许配置更高容量。
- iOS 始终提供稳定 `deviceId`；旧客户端缺失时后端使用受控 fallback，不破坏兼容性。
- 本轮不改变公开 UI 和数字人供应商。
