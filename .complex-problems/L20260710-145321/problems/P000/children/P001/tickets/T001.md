# 实现内存与 Postgres Session Lease Store

## Problem Definition

Store 层没有数字人 session 状态，无法对多设备并发做原子仲裁，也无法在客户端崩溃后通过 TTL 回收逻辑容量。

## Proposed Solution

新增 `digital_human_sessions` Postgres 表和内存映射，实现 acquire、heartbeat、release、get。Postgres acquire 在 resource/device 两个稳定 key 上使用事务 advisory lock，锁内清理过期 lease、复用相同 context、释放同设备旧 context、检查资源容量并插入。所有持久化 payload 只保存 lease 元数据。

## Acceptance Criteria

- 内存与 Postgres API 返回统一 outcome。
- 同 context 复用，同设备切换替换，跨设备超额冲突。
- heartbeat owner 校验、TTL 延长、release 幂等。
- 数据库 schema/index 和事务锁受测试保护。
- 不保存 credential、asset secret 或 access token。

## Verification Plan

先补 InMemoryStore/PostgresStore 失败测试和 FakeConnection 合同，再实现；运行 `tests/test_postgres_store.py`、完整 backend tests、编译与 diff check。

## Risks

- FakeConnection 必须忠实覆盖新增 SQL 语义，不能让测试只匹配字符串而遗漏状态转换。
- advisory lock key 顺序必须稳定，避免 device/resource 交叉死锁。

## Assumptions

- Session lease 容量由调用方传入，store 不读取全局 settings。
- 时间统一使用带时区 ISO-8601。
