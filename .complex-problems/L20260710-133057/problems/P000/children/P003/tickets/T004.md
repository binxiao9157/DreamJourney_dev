# 收敛 runtime 代际、音频 owner 与失败恢复

## Problem Definition

Echo 虽有单一 runtime 属性和 audio owner 日志，但 runtime 未显式绑定 lifecycle generation；配额、旧 PCM 尾段和延迟恢复需要统一证明不会影响新角色。

## Proposed Solution

为当前 runtime 记录 lifecycle generation，音频路由与 runtime 回调只接受当前代际。保留用户停止/点击打断的 session，页面退出和终止失败统一释放。配额失败明确排除自动重连。扩展 Phase 2 静态检查和既有 audio-owner guard，并运行数字人/复刻组合 gate。

## Acceptance Criteria

- 同一时刻只有一个 runtime，且其 generation 与当前 lifecycle 一致时才可拥有音频。
- 旧 runtime callback、复刻响应、PCM chunk/final 和延迟恢复不能作用于新角色。
- 用户停止/打断保留 session；页面退出和失败释放。
- 配额满立即回普通 Echo，不进入 recovery。
- 相关静态检查、组合 gate、模拟器构建与 diff check 通过。

## Verification Plan

运行 Phase 1/Phase 2、audio-owner/stop、lifecycle coordinator guard；运行 digital-human/voice-clone 非真机组合 gate；执行 iOS Simulator Debug 构建和 `git diff --check`。

## Risks

- 非真机 gate 不能证明腾讯 SDK 的真实音频听感与口型同步。

## Assumptions

- 本阶段按用户要求暂停真机验证，真机只作为后续验收门。
