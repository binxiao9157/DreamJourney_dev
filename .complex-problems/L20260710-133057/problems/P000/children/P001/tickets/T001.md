# 用统一 token 保护 Echo 数字人异步工作

## Problem Definition

局部 request/context guard 无法覆盖 capability、realtime token、synthesis 和延迟恢复，旧角色或旧页面回调可能修改当前 Echo。

## Proposed Solution

在 `DigitalHumanConversationCoordinator.swift` 增加 `DigitalHumanLifecycleCoordinator` 和不可变 token。Echo 维护当前 context generation，在角色切换、页面退出和终止释放时推进；异步入口捕获 token，回调通过统一 helper 校验。PCM 保留 request/context 检查并叠加 token。

## Acceptance Criteria

- token 包含 generation/context 并可判定 stale。
- 角色切换、页面退出使旧 token 失效。
- session、capability、realtime、synthesis、PCM、resume 关键路径均有 token guard。
- 现有正常流程与 QA smoke 不改变业务输出。

## Verification Plan

新增 Phase 2 静态 guard 检查 token API 与关键调用点；编译并运行 coordinator、现有 session/audio owner 检查和相关模拟器 smoke。

## Risks

- token 推进过于频繁会误丢有效回调。
- 旧 PCM 定时闭包数量较多，必须保留 requestID guard。

## Assumptions

- 不修改后端合同。
- 所有相关 UI 更新都在主线程执行。
