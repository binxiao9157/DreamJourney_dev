# 增加 lifecycle coordinator 可执行状态检查

## Problem Definition

现有 Phase 2 静态检查只能确认 token guard 已接入源码，不能直接证明协调器在 context 切换、交互失效与页面失效时的状态转换。

## Proposed Solution

新增一个带 `@main` 的 Swift 状态检查文件，与生产 `DigitalHumanConversationCoordinator.swift` 一起通过 `swiftc` 编译执行。断言 session generation、interaction generation、context 与后台 lease 的有效性变化。

## Acceptance Criteria

- 首次 context token 可用。
- context 切换后旧 session 与 interaction token 均失效。
- interaction 失效后旧 interaction token 失效，但同代 session token仍可用于 session 回调。
-页面级失效后旧 session token 失效。
-后台 release lease 可取消，且生命周期失效后不可继续生效。

## Verification Plan

使用 `swiftc` 同时编译生产协调器与 QA check，执行产物并要求退出码为 0；随后重跑 Phase 2 静态检查。

## Risks

- 检查只验证纯状态机，不替代 UIKit 生命周期和真实腾讯 SDK 行为验证。

## Assumptions

- `DigitalHumanConversationCoordinator.swift` 保持只依赖 Foundation，可被独立编译。
