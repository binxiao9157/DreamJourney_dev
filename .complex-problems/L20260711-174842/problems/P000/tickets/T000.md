# 实现本地知识文件保护与语义缓存隔离

## Problem Definition

当前语义 embedding cache 只按实体 ID 缓存、使用无锁共享字典和全局预热状态；跨账号、跨实体类型、内容更新或旧异步预热可能复用错误向量。graph、remote base、pending mutation、governance outbox、legacy sync history 虽大多原子写入，但目录、文件保护与备份排除策略分散，无法证明所有敏感知识持久化都受到同一保护。

## Proposed Solution

在不改变现有知识文件路径、JSON envelope 和公开 UI 的前提下，引入 owner digest + KBLite generation 的语义 cache scope，使用 entity kind + ID + searchable text fingerprint 构造 cache key，并用锁与 scope token 拒绝旧异步写入。新增统一 `KnowledgeLocalStoragePolicy`，集中处理目录准备、backup exclusion、`completeUntilFirstUserAuthentication` 与 atomic write，并接入全部五类知识持久化入口。

## Acceptance Criteria

- 语义缓存 scope 同时绑定不可逆 owner key 和 KBLite generation。
- entity kind、entity ID、searchable text fingerprint 共同决定缓存 key。
- 账号切换、登出和 generation 变化会立即失效旧 cache，旧异步 warm 不得写入新 scope。
- cache 字典不存在无锁并发读写。
- graph/base/pending/outbox/sync history 使用统一 storage policy，并保持现有文件名和 envelope 兼容。
- storage policy 使用 atomic write、`completeUntilFirstUserAuthentication` 和 backup exclusion。
- 新增 gates 接入 release regression/release QA；Simulator、generic iPhoneOS build 和 `git diff --check` 通过。

## Verification Plan

1. 先新增 semantic cache scope/content/concurrency gate 与 storage protection gate，使其在旧实现上失败。
2. 实现纯 scope/key 模型、线程安全 cache 和 KBLite 生命周期接线。
3. 实现统一 storage policy 并接入五类知识持久化入口。
4. 运行新增 gates、现有 knowledge pipeline/merge gates、release QA package。
5. 运行 Simulator Debug 与 generic iPhoneOS build，不做真机。

## Risks

- 文件保护在 Simulator/macOS 测试环境的行为与真机不同，因此必须以编译和静态合同证明接线，但不能宣称真机静态数据保护已验收。
- 旧预热任务与账号切换并发，必须先切 scope 再允许新 graph 参与检索，不能仅在 warm 结束时清空。
- 现有注入临时目录的 store 测试必须保持可运行，统一策略不能假定只有沙盒 Documents/Application Support。

## Assumptions

- `completeUntilFirstUserAuthentication` 满足后台同步与静态数据保护之间的当前产品取舍。
- 本轮不引入网络 embedding、向量数据库或新缓存基础设施。
- 本轮不移动或批量删除现有用户文件，不改 Echo/Stitch UI，不做真机验证。
