# 接入统一知识文件保护策略

## Problem Definition

五类知识 JSON writer 分布在三个服务中，只有 atomic write 较一致；文件/目录 protection 和 backup exclusion 缺失，旧文件读取时也不会补强属性。

## Proposed Solution

新增 `KnowledgeLocalStoragePolicy`，提供 `prepareDirectory`、`hardenExistingItem`、`write` 三个集中 API。写入使用 atomic + complete-file-protection-until-first-authentication，随后加固最终 inode 并排除备份。graph、sync history、base、pending、outbox 只通过该策略写入；读取前对既有目录/文件 best-effort 加固，保持原路径和 envelope。

## Acceptance Criteria

- 五类 writer 不再直接调用 `Data.write(... .atomic)`。
- 统一 policy 明确使用 `completeUntilFirstUserAuthentication` 和 `isExcludedFromBackup`。
- 原子替换后重新加固最终文件。
- 既有文件加载前尝试加固，失败不删除或改写用户数据。
- 临时目录注入的 store 测试保持兼容。
- 新 static gate、既有 merge/store gates 和两种非真机构建通过。

## Verification Plan

- 先新增静态 gate，检查 policy 与五个 writer 的接线并在旧实现失败。
- 实现 policy 并接入目标 writer/reader。
- 运行 knowledge merge/outbox/model gates、release QA、Simulator 和 generic iPhoneOS build。

## Risks

- macOS host 测试不完全模拟 iOS Data Protection；静态与编译证据不能替代真机锁屏验收。
- backup exclusion 或 protection 属性在不支持的临时文件系统上可能失败，不能因此破坏注入目录的业务读写测试。

## Assumptions

- 当前需要保护但允许首次解锁后后台访问，因此采用 `completeUntilFirstUserAuthentication`。
- 本轮不移动 Documents graph，不改变文件 envelope。
