# 实现 generation-bound 语义缓存

## Problem Definition

当前语义 cache 既没有账号/generation namespace，也没有线程同步和内容指纹；旧 warm task 与新账号搜索可以并发访问同一字典。

## Proposed Solution

在 `KBLiteSemanticSearch` 内定义纯 `KBLiteSemanticCacheScope` 与 `KBLiteSemanticCacheKey`，使用 owner digest、generation、entity kind、ID 和文本 fingerprint。由锁保护 active scope 与 embedding cache；`KBLiteManager` 在 init/switch 时激活 scope，并在 warm/search 时传入同一 scope。旧 scope 写入必须被拒绝。

## Acceptance Criteria

- 相同 ID 在不同账号、generation、类型或文本下不共享 cache key。
- cache key 和日志不含 raw userId 或正文。
- 账号切换先激活新 scope，再 warm 新 graph。
- 所有 embedding cache 读写都位于锁保护 API 内。
- 旧 warm callback 在 scope 不匹配时不写入。
- 新模型/static gates 和相关知识检索 gate 通过。

## Verification Plan

- 先新增纯模型 smoke 覆盖 scope/key 差异和旧 scope reject。
- 新增 static gate 固定 KBLite lifecycle 接线、锁与关键词 fallback。
- 运行新增 gates、knowledge pipeline/context gates 和 iOS build。

## Risks

- NaturalLanguage embedding 在 CI/Simulator 可用性不稳定，因此正确性验收应基于纯 cache policy，不依赖模型是否下载。
- generation 读取必须与 graph snapshot 同步，避免 scope 与 graph 不一致。

## Assumptions

- 语义 cache 只保存在进程内，不需要磁盘迁移。
- owner digest 可复用知识同步 userKey 的不可逆散列语义，但不能产生模块循环依赖。
