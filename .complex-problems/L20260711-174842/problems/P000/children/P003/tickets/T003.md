# 在 ranking 前隔离 persona 候选并接入发布门

## Problem Definition

generation Context 目前先对账号整图做 semantic top-K，再按 expected persona/evidence/privacy 过滤；不属于当前 persona 的高相似实体可能挤占候选。Task 23 新增 gates 也尚未进入默认 release 回归。

## Proposed Solution

把 KBLite 的 search 核心改为接收不可变 graph snapshot；生成 Context 先根据同一 `canGenerate` 与 `entityIsVisible` policy 构造 persona-visible candidate graph，再进行 semantic/keyword ranking，排名后保留现有二次过滤。新增顺序 static gate，并把 semantic cache/storage 四条 runner 与该 gate 接入 release regression/release QA package。

## Acceptance Criteria

- generation Context 的 people/places/events/facts 在 ranking 前完成 persona、privacy、evidence 过滤。
- ranking 后保留二次过滤，避免未来 search 改动绕过边界。
- 普通 `search(query:)` 继续搜索当前账号全图，不改变知识页行为。
- semantic 和 keyword fallback 使用同一传入 snapshot，不回读另一账号 graph。
- Task 23 新 gates 默认进入 release regression 和 QA package。
- 完整非真机回归与两种构建通过。

## Verification Plan

- 新增 static gate 固定 prefilter-before-search 顺序和二次过滤。
- 运行 cache/storage/context/pipeline/model gates。
- 运行 release QA package、完整 release regression、Simulator 与 generic iPhoneOS build。

## Risks

- 复制 KBLiteGraph 可能有小额内存开销，但实体上限固定且只在构建 Context 时发生。
- 必须确保 related facts 仍使用同一 persona policy。

## Assumptions

- 当前 KB 实体上限允许生成一次值语义 candidate snapshot。
- 本轮不改变排序阈值或 UI。
