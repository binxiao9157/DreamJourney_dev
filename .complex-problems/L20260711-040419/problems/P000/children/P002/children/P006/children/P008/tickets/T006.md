# 将 Archive DELETE 编排到 deleteSource 与 Context

## Problem Definition

即使 store 有组合事务，现有 DELETE endpoint 仍不会构建 source mutation，也不会返回 cascade 证据；Context 回归也尚未证明受影响实体不可生成。

## Proposed Solution

DELETE endpoint 获取当前 snapshot/revision，使用 `build_knowledge_governance_mutation` 构建 `deleteSource(memoryArchiveItem,itemId)`；source 不存在时使用 mutation=None。调用 store 组合原语并映射 missing/sealed/revision/validation。支持可选 query `operationId`，缺失时生成一次性安全 ID。响应保留 `status/id/item` 并增加 `cascade`（operationId、revision、duplicate、affectedEntityCount、action），不返回知识正文。增加 API/change feed/Context 测试。

## Acceptance Criteria

- 四类 source-matched 实体随 Archive 删除变为 superseded、source ref 被移除。
- Context generation 不包含这些实体；change feed 记录同一 operation mutation。
- 无知识引用的 archive 正常删除且 revision 不伪增。
- sealed、missing、revision conflict 和 duplicate 映射稳定。
- 旧 DELETE 调用不传 query 仍兼容。

## Verification Plan

FastAPI memory tests 覆盖有/无知识、四实体、change feed、Context；store tests 覆盖的 transaction 证据复用 P007。运行知识 evidence/context、archive 和全量 tests。

## Risks

- 读取 snapshot 与 transaction 之间变化会产生 409，需要确保不会提前删除素材。
- 旧 `archiveImageAnalysis/session-N` source ref 不匹配 item ID，只能作为迁移缺口记录。

## Assumptions

- 新知识来源使用 canonical `memoryArchiveItem`。
- iOS 下一子票会在主动删除时提供 operation ID 并消费 cascade。
