# 实现 Archive 与 Knowledge 的单事务删除原语

## Problem Definition

两种 store 缺少一个同时验证 archive、knowledge revision 并提交 Mutation V2 与删除素材的原子方法。上层无法靠多个现有方法保证 rollback 和并发一致性。

## Proposed Solution

抽取/复用当前 `apply_kb_mutation` 的内部步骤，新增 `delete_archive_item_with_kb_mutation(user_id,item_id,operation_id,base_revision,mutation)`。MemoryStore 在嵌套可重入 locks 下先检查 duplicate/revision/item/sealed，再应用 mutation并删除。Postgres 使用单 connection/cursor、用户 knowledge advisory lock 和 archive row lock；同 transaction 查询 duplicate、snapshot revision、验证 sealed，写 snapshot/change 后 delete，统一 commit/rollback。mutation 可为 None，表示无知识引用但仍做 revision 检查。

## Acceptance Criteria

- 两种 store 返回统一的 deleted item、duplicate、revision、mutation 和 graph 摘要。
- mutation 非空时只增加一次 revision/change；duplicate operation 不重复删除或增加 revision。
- revision mismatch、sealed、missing 和 SQL failure 不改变 archive/snapshot/change。
- 旧 apply_kb_mutation 输出与测试保持一致。

## Verification Plan

定向 memory/Postgres fake tests 覆盖成功、无 mutation、revision conflict、duplicate、sealed、missing、失败 rollback；运行既有 knowledge V2 与 archive tests、compileall、diff check。

## Risks

- cursor helper 重构可能改变现有 mutation commit 时机。
- duplicate delete 时 archive 已不存在，需要从 change record 恢复足够的幂等摘要而不能伪造 deleted item。

## Assumptions

- operation ID 只在 mutation 非空时写入 kb_changes；无 mutation 的旧客户端删除不承诺跨请求幂等。
- sealed 规则可以在 store 层用现有 kind/deliveryState 合同判断。
