# 阻止 Archive ID 跨用户接管

## Problem Definition

Postgres archive 全局主键冲突更新会覆盖 `user_id`，InMemoryStore 又允许不同用户复用同 ID，导致同一 API 在两种 store 下 owner 语义不一致，并可能让来源级联作用于错误用户。

## Proposed Solution

新增 `ArchiveItemOwnershipConflict`。InMemoryStore 在写入前扫描其他用户的同 ID；Postgres `archive_items` 使用 owner-aware upsert，冲突行 owner 不同则不更新并抛出业务异常。仅调整 archive 写入，不改变其他 generic payload 表。`/archive/photos`、`/archive/items` 捕获异常并返回不暴露原 owner 的 409。

## Acceptance Criteria

- 同 owner 同 ID 更新成功并保留兼容行为。
- 不同 owner 同 ID 在 memory/Postgres 均失败，原记录保持不变。
- API 返回 409 固定 detail/code，不返回原 owner ID。
- timeLetter 封存/更新、普通 archive smoke 与既有测试通过。

## Verification Plan

增加 memory/API/Postgres fake connection 测试，运行 archive/time-letter 相关测试、全量 backend verify 和 diff check。

## Risks

- 通用 `_insert_payload` 仍服务其他表，必须避免无关行为变化。
- 旧数据库可能已存在被错误接管记录，本票只阻止新冲突，不猜测历史 owner。

## Assumptions

- archive ID 对全服务是不可跨 owner 复用的稳定标识。
- 生产客户端通常使用 UUID；冲突代表错误或攻击，不需要自动改名。
