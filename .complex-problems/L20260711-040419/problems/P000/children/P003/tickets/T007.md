# 实现 iOS 知识治理模型、Outbox 与权威消费

## Problem Definition

iOS 目前只能发送通用 graph mutation，无法表达 confirm/reject/correct/deleteSource，也会在 Codable 重写时丢失后端 governance metadata。显式用户动作如果遇到网络、revision conflict 或用户/角色切换，没有可恢复队列和权威 snapshot 应用边界。

## Proposed Solution

在现有知识文件中增加强类型治理 enum、entity/source references、四类 typed correction、metadata/summary/response。四类 KBLite entity 增加 optional governanceMetadata 以保真。Backend client 新增 `/kb/governance/actions` 调用与 `/archive/items/...?...operationId=` delete consumer。

在 `KnowledgeSyncCoordinator` 增加 per-user 持久化 governance outbox 和公开 `performGovernance`。动作先落盘，再在现有串行 queue 中基于 remote base revision 提交；409 先 refresh change feed 再重试。成功时只在 active user 和 captured persona generation 仍匹配时直接应用权威 graph；角色已切换则移除已确认 outbox、通过普通 change feed 刷新，不直接使用旧角色 callback。失败保留 outbox供重启恢复。

## Acceptance Criteria

- 四类 action 只能通过合法 typed constructors 构造并编码为 schemaVersion=1。
- governance metadata 在 KBLite 本地导入导出和三方合并后不丢失。
- client 解析 revision/duplicate/summary/authoritative graph，错误保持现有 ClientError。
- outbox 按 user 隔离、原子持久化、重启可读；成功删除，失败保留。
- governance 与普通 sync 不并发；revision conflict 可 refresh/retry。
- 用户切换和 persona 切换后的旧 callback 不直接写入当前图谱。
- 不新增公开 UI。

## Verification Plan

新增 Swift model/outbox smoke，静态 guard 检查 coordinator/client/generation 边界；扩展三方合并模型验证 metadata 保真。运行相关脚本、generic Simulator build、release regression 最终由 P004 统一执行。

## Risks

- 现有 pending graph mutation 是单槽文件，治理必须用独立 outbox，不能复用。
- KBLite `save()` 会触发普通同步，coordinator 必须 coalesce 而非形成循环。
- persona 切换后服务端动作可能已成功，不能重发造成新 correction；operation ID 幂等和 change-feed refresh 必须配合。

## Assumptions

- 本轮只提供可调用 API/QA，不放公开审阅入口。
- active user graph 可以包含多 persona，但旧 persona callback 不能直接驱动当前角色 UI/完成态。
- backend governance response 的 graph 是权威 snapshot。
