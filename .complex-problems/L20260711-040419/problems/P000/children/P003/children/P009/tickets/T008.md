# 落地 iOS 治理模型与 Backend Client

## Problem Definition

iOS 缺少治理 action/response 类型，现有实体无法保留 governance metadata；若直接使用字典，纠正字段和 schema 很容易漂移。

## Proposed Solution

在 `KBLiteModels.swift` 增加 entity/source link、governance metadata、typed correction structs 和 custom Codable action enum；提供稳定 `jsonObject` 供 client 使用。四类实体增加 optional metadata。定义 response/summary consumer（权威 graph 保持 `[String:Any]`，summary 强类型）。在 `DreamJourneyBackendClient` 增加 governKnowledge 和带 operationId 的 deleteArchiveItem，严格校验 schema/revision/graph/summary。

## Acceptance Criteria

- 四类 action 不能编码出不合法字段组合。
- correct 的 correction 类型与 entityType 一致。
- metadata 在实体 JSON round-trip 保留 target/replacement/sourceRef。
- client 请求包含 schemaVersion/user/operation/base/action，响应缺字段失败。
- Archive delete operationId URL 编码安全。

## Verification Plan

新增独立 Swift model smoke，构造四类 action、metadata round-trip、response parser；新增 source guard 验证 client path和 required fields。运行 Swift 脚本与 generic build（最终 build 可在 P004）。

## Risks

- 自定义 enum Codable 必须兼容持久化 outbox。
- 后端 graph 日期/legacy top-level 字段不稳定，client 不应直接强制解码为 KBLiteGraph。

## Assumptions

- authoritative graph 由 coordinator 交给现有 `applySyncedGraph`。
- 本票不实现 outbox 和公开 UI。
