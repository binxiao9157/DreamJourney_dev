# 建立按用户持久化的 Governance Outbox

## Problem Definition

现有 KnowledgePendingMutationStore 每用户只有一个 graph delta，不适合多个显式治理动作，也无法保存 expected persona identity。需要独立、可重启恢复的动作队列。

## Proposed Solution

在 `KnowledgeThreeWayMerge.swift` 增加 `KnowledgeGovernanceOutboxItem`（operationId,userId,expectedOwner/persona/digitalHumanId,action,createdAt）和 `KnowledgeGovernanceOutboxStore`。每用户文件使用现有 hash key，JSON schemaVersion=1，ISO8601 日期，原子写。enqueue 按 operationId 更新但保持原队列位置，load 有序，remove 单项/全量。损坏 envelope 抛 `invalidPersistenceEnvelope`，coordinator 可移除。

## Acceptance Criteria

- item/action/identity round-trip 完整。
- user A/B 文件互不影响。
- 同 operation enqueue 不重复，顺序稳定。
- remove 单项、空队列删除文件、removeAll 正确。
- 损坏 schema/userKey/action 被拒绝。

## Verification Plan

新增独立 Swift outbox model smoke，用临时目录覆盖所有路径，并重跑 governance/three-way model smoke与 diff check。

## Risks

- 复用现有 KnowledgeSyncModelError 时要保持旧 base/pending 行为。
- action custom Codable 日期策略必须和模型自定义编码兼容。

## Assumptions

- 队列规模很小，整文件原子重写足够。
- coordinator 决定错误清理和网络重试，本票只提供存储原语。
