# 运行期家庭授权刷新与异步 identity generation

## Problem Definition

当前家庭 authority 能在登录、冷启动和已知列表变化时刷新，但前台长期运行期间可能继续使用已被服务端撤销的 family persona；extraction/governance 的回调仍通过当前 context 重新解析 repository；选中 family 失效时没有主动通知 Echo 重置。

## Proposed Solution

为 FamilyRepository 增加 owner-bound authorization generation、刷新状态和刷新完成 API。前台恢复先刷新家庭 authority，再触发知识同步；刷新失败把授权快照标记为不可用于新权限判断。知识 extraction/governance 在主线程发起时捕获 identity + family authorization generation，异步完成只比较捕获 token 和账号 generation。FamilyRepository 每次授权集合失效后调用 DigitalHumanContextStore 主动 reconcile，持久化 self context 并发送统一 context change。

## Acceptance Criteria

- 服务端撤销、刷新失败和账号切换都会使旧 family authorization generation 失效。
- foreground 不会在家庭刷新完成前启动新的 family knowledge sync。
- extraction/governance 后台回调不直接读取 FamilyRepository；stale identity/generation 结果被拒绝。
- 当前 family context 失效时主动回退 self 并广播，Echo 现有 context observer 可取消旧 gate/runtime 请求。
- Task 22 gates、专项 stale callback smoke、全量 release regression、Simulator/generic iPhoneOS build 通过。

## Verification Plan

先补纯模型/静态 smoke 覆盖刷新成功、撤销、失败、账号切换和旧 callback；再实现 repository snapshot/token、foreground 顺序、extraction/governance capture、context reconciliation。运行后端 family targeted tests、Task 22 gates、`git diff --check` 和全量非真机 release regression。

## Risks

- 网络失败时 fail closed 会暂时使 family Echo 回退 self，需要保留家庭列表展示但不能继续授予知识权限。
- foreground 刷新不能阻塞 UI；同步应在 completion 后异步启动。
- 避免 FamilyRepository、DigitalHumanContextStore、KnowledgeSyncCoordinator 单例初始化形成递归。

## Assumptions

- 后端 family list/accept 合同继续是唯一生产 authority。
- 本任务不新增撤销 UI，也不修改后端路由。
- QA fixture 仍只在 UI_QA_SIMULATOR 构建中获得显式授权。
