# 更新旧发布门以验证不可变授权快照

## Problem Definition

既有 proposal/persona 静态检查仍把后台重新解析当前 persona 当作正确行为，与 P008 的不可变 generation snapshot 合同冲突并阻断 release regression。

## Proposed Solution

更新 `knowledge-proposal-persona-policy-check.swift`：要求 `ConversationMemoryManager` 在后台派发前捕获 `KBPersonaAuthorizationSnapshot`，要求 `KBLiteManager.finishExtraction` 只调用锁内 snapshot policy，并显式禁止其中出现 `resolveCurrentPersonaIdentity()` 或 `FamilyRepository`。保留 proposal-first、evidence 和 Echo family fallback 既有断言。

## Acceptance Criteria

- proposal/persona gate 不再断言旧 resolver 双重读取。
- gate 明确验证主线程捕获、snapshot 传递及后台完成阶段禁止读取可变授权源。
- proposal/persona、async snapshot、governance coordinator 与 release QA package 全部通过。
- `git diff --check` 与 Simulator build 通过。

## Verification Plan

运行 `run-knowledge-proposal-persona-policy-check.sh`、`run-knowledge-async-authorization-snapshot-check.sh`、`run-knowledge-governance-coordinator-check.sh`、release QA package、`git diff --check`；复用 P008 已通过的 Simulator build，并在后续全量回归再次构建。

## Risks

- 静态函数体解析若过宽可能误判相邻函数，使用现有 brace-depth helper 限定函数体。

## Assumptions

- P008 运行时代码和模型保持不变，本票只修正既有验证合同。
