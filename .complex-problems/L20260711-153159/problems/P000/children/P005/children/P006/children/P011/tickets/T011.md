# 用 refresh token 与 authorization epoch 封闭并发失效窗口

## Problem Definition

同账号并发家庭 refresh 仅绑定账号 generation，旧响应可能覆盖较新结果；coordinator 的角色/授权失效异步排队，旧 callback 可能先于失效块写入 graph/base/outbox。

## Proposed Solution

FamilyRepository 在 `beginRefresh` 后捕获 freshness generation，并通过纯 response acceptance policy 同时比较 owner、user generation 和 refresh generation。KnowledgeSyncCoordinator 增加锁保护 authorization epoch：本地账号、角色、家庭刷新开始时先同步轮换 epoch，再同步更新 queue-owned generation；`isCurrent` 同时验证 queue generation 与当前 epoch，使已排队旧 callback 在任何写入前失败。

## Acceptance Criteria

- refresh A/B 任意乱序时只有最后一次请求响应可更新 authority；旧成功和旧失败均返回 stale。
- persona/family invalidation 调用返回前已轮换 epoch 和 queue generation。
- callback 即使先入队，只要失效先线性化，就不能通过 `isCurrent` 修改 graph/base/outbox。
- queue 内调用不会因 `queue.sync` 自锁；主线程不等待任何 queue -> main sync。
- 模型/静态 gate、Task 22 gates、release QA、完整 regression 与两种非真机构建通过。

## Verification Plan

扩展 freshness 模型并新增 coordinator authorization epoch 模型/静态 gate；运行知识治理、三方合并、家庭授权、Echo context、release QA、全量 release regression、Simulator 和 generic iPhoneOS build。

## Risks

- 同步 queue invalidation 会短暂等待正在执行的本地 commit；队列不使用 main.sync，避免互锁。
- epoch 必须在每个新 sync generation 建立时同步绑定，否则会永久拒绝新 callback。

## Assumptions

- 网络 callback 的所有图谱/base/outbox写入路径均先经过 `isCurrent` 或 governance callback 的同一 generation guard。
