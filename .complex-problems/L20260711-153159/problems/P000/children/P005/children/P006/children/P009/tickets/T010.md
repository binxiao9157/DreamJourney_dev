# 家庭授权撤销时主动回退本人 Echo Context

## Problem Definition

当前持久化 family context 在服务端撤销、刷新失败或授权记录失效时，getter 可能只临时返回本人默认值；若未持久化并广播，Echo UI/runtime、知识角色和治理队列仍可能保留旧家人角色。

## Proposed Solution

让 `acceptedMember(by:)` 受授权 freshness 约束；FamilyRepository 授权集合变化或失败后调用 `DigitalHumanContextStore.reconcileFamilyAuthorization()`。ContextStore 在主线程读取原始持久化 family context，确认失效后写回本人默认 Context，并通过既有通知驱动 Echo runtime、KBLite persona generation 和 governance persona 一起切换。增加纯 reconciliation policy 模型与源码 gate。

## Acceptance Criteria

- 刷新失败或 family member 被撤销后，旧 family context 持久化回当前用户 self。
- 只对真正失效的 family context发送 `djDigitalHumanContextDidChange`，正常 accepted family 不产生额外回退。
- Echo observer 收到通知后取消/释放旧 runtime 请求并准备 self runtime。
- KBLite 和 KnowledgeSyncCoordinator 同步切换当前 persona。
- 专项模型、静态 gate、release QA、`git diff --check` 和 Simulator build 通过。

## Verification Plan

新增 family context reconciliation model/static smoke 并接入 release regression；运行 family freshness/repository/Echo authorization gates、release QA 和 Workspace Simulator build。

## Risks

- 回退通知可能与 UI 主动切换同时发生；setter 通过当前用户 owner-scoped key 和相同值去重避免重复广播。

## Assumptions

- Echo 已观察 `djDigitalHumanContextDidChange` 并通过现有 generation 机制取消旧 runtime。
