# 用 freshness generation 拒绝旧家庭响应

## Problem Definition

同账号多次 `refreshFromBackend` 共享 user generation，旧请求回调无法与最新请求区分。

## Proposed Solution

在 `beginRefresh()` 后捕获 `authorizationFreshness.generation`，通过纯 `FamilyAuthorizationRefreshResponsePolicy` 同时比较 owner、user generation 和 refresh generation；任何一项不匹配均返回 stale，不执行 replace/invalidate。

## Acceptance Criteria

- A/B refresh 中 B 开始后 A 响应必定拒绝。
- B 完成并再次轮换 generation 后 A 响应仍拒绝。
- 账号切换和 owner 不匹配保持拒绝。
- freshness 模型和 repository lifecycle gate 通过。

## Verification Plan

扩展 `family-authorization-freshness-model-smoke.swift` 覆盖 A/B 乱序；扩展 repository static gate；运行 Task 22 相关检查和 Simulator build。

## Risks

- 旧请求 completion 将收到 stale error，但不会改变已验证 authority。

## Assumptions

- `FamilyAuthorizationFreshness.generation` 每次 begin/success/failure/reset 都轮换。
