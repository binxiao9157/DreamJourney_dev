# 用 authorization epoch 线性化 coordinator 失效

## Problem Definition

角色或家庭授权失效通过 `queue.async` 延后执行；旧网络 callback 若已排队，可先用旧 generation 修改 graph/base/outbox。

## Proposed Solution

增加锁保护 `KnowledgeAuthorizationEpochState`。账号、角色和家庭刷新开始先同步 rotate epoch，再通过 queue-specific 安全的同步执行更新 queue generation；每个 active sync generation 绑定 epoch，`isCurrent` 同时验证 user、generation 与当前 epoch。

## Acceptance Criteria

- 本地 invalidation 一开始就使旧 active epoch 失效。
- 已排队 callback 在任何写入 guard 处因 epoch 不匹配返回。
- queue state 在 invalidation API 返回前完成更新。
- queue 内重入不会 `queue.sync` 自锁，代码不存在 queue -> main sync。
- epoch 模型、静态 gate、governance/knowledge sync gates 和构建通过。

## Verification Plan

扩展 context policy model，新增 coordinator epoch static gate；运行 governance coordinator、async snapshot、three-way merge、release QA 和 Simulator build，最终由父任务跑全量 regression/generic iPhoneOS。

## Risks

- 所有新 generation 都必须绑定当前 epoch；静态 gate 固定每个 generation 赋值点。

## Assumptions

- coordinator 网络 callback 在写 graph/base/outbox 前均经过 `isCurrent` 或 `isCurrentPull`。
