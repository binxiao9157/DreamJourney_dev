# 运行期家庭授权新鲜度与异步快照复核

## Summary

R009 完成三个计划子问题，但独立并发时序审查证明同账号 refresh 乱序和 coordinator invalidate 排序仍可让旧 authority 结果生效，因此 P006 当前不能判定成功。

## Evidence

- P007/P008/P009 的模型、静态 gate 和 Simulator build 通过。
- FamilyRepository refresh callback 只捕获 `userGeneration`，未比较本次 `authorizationFreshness.generation`。
- coordinator 的 persona/auth invalidation 使用 `queue.async`，而网络 callback 也异步入同一队列；setter 返回不代表旧 callback 已失效。

## Criteria Map

- foreground refresh 与失败 fail closed：基本满足，但并发旧 refresh 可覆盖新结果。
- extraction immutable snapshot：满足。
- governance stale callback 不写 graph/base/outbox：未完全满足，失效排序存在窗口。
- Echo context 主动回退：满足。

## Execution Map

- R009 汇总 P007/P008/P009；新增并发缺口必须作为独立 follow-up 实施。

## Stress Test

- 推演 refresh A/B 乱序：B 成功后 A 失败仍可调用 `invalidateAuthorization`。
- 推演 callback 已入队、随后 context setter 入队：callback 可能先应用 authoritative graph，再执行失效块。

## Residual Risk

- 未修复前，服务端撤销或角色切换附近仍可能短暂写入旧知识 base/outbox 状态。

## Blocking Gaps

- 为每次家庭 refresh 捕获并比较独立 refresh generation。
- 让 persona/family authority invalidation 在调用返回前同步完成，或用可在线程安全位置立即轮换的外部 generation 阻断已排队 callback。
- 增加乱序 refresh 与 callback-before-invalidate 模型/静态回归。
