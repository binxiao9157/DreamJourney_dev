# 用 generation token 固化知识提取与治理授权

## Problem Definition

知识提取结束和 governance queue 会重新调用当前 persona resolver，导致后台线程读取 FamilyRepository，并可能在账号/家庭授权切换时接纳旧结果。

## Proposed Solution

新增可传递的 `KBPersonaAuthorizationSnapshot`，在会话结束的主线程捕获 identity、KBLite user generation 与 family authorization generation。FamilyRepository 每次 refresh generation 变化都发布给 KBLiteManager 的锁保护状态；finishExtraction 只比较 snapshot 和锁内 generation。Governance 改用 queue-owned `KnowledgeSyncAuthorizationScope.allows(identity:)` 验证 outbox item，不再在 queue 上解析当前 context/repository。

## Acceptance Criteria

- family extraction 没有 generation token 时 fail closed。
- refresh start/success/failure 与账号切换使旧 extraction snapshot 失效。
- extraction finish 不调用 `resolveCurrentPersonaIdentity()`。
- governance start/success 不调用 persona resolver，只使用 active sync authorization + sync generation。
- 模型/static gate 与 Simulator build 通过。

## Verification Plan

增加 async authorization snapshot model/static smoke，扩展 extraction/governance source checks，运行知识 proposal/governance/Task 22 gates 和 workspace Simulator build。

## Risks

- 旧调用点若未提供 family token 将被拒绝，personal flow 保持兼容。
- refresh 中完成的旧 extraction 会被丢弃，下一轮对话可重新提取。

## Assumptions

- ConversationMemoryManager.endSession 在主线程捕获当前 persona。
- KBLite graphLock 是 user/family generation 的统一线程安全边界。
