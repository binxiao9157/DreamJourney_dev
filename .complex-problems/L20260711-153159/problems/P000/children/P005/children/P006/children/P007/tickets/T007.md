# 引入 owner-bound 家庭授权刷新状态并串联 foreground

## Problem Definition

FamilyRepository 只保存成员数组，无法区分“已验证”“刷新中”“刷新失败”；foreground 直接同步知识，可能继续使用服务端已撤销的旧 accepted family。

## Proposed Solution

增加家庭授权 refresh state、authorization generation 和 owner-bound snapshot。成功刷新以权威列表替换成员；失败使授权 snapshot fail closed 但保留列表仅供展示。Scene foreground 调用带 completion 的家庭刷新，完成后再启动知识同步。授权 generation 变化统一通知 KnowledgeSyncCoordinator 清 base/re-pull，并触发 DigitalHumanContextStore reconcile。

## Acceptance Criteria

- 只有 ready snapshot 能向同步/Echo 提供 accepted family。
- backend failure、非法记录、账号切换使旧 snapshot 失效并递增 generation。
- foreground 刷新完成后才调用 `synchronizeCurrentUser`。
- stale response 不污染新 owner；QA fixture 只在 UIQA 显式进入 ready。
- 专项 gate 和 workspace Simulator build 通过。

## Verification Plan

扩展 family repository lifecycle static gate，增加纯 refresh-state 模型 smoke；运行 Task 22 四 gate、`git diff --check` 与 workspace Simulator build。

## Risks

- 网络失败时 family Echo 会 fail closed 回 self，但成员列表仍保留用于解释状态。
- 同一授权集合重复刷新不能触发无意义的 base 清理。

## Assumptions

- `/family/members/{userId}` 是完整权威列表。
- foreground 刷新为异步，不阻塞 UI 主线程。
