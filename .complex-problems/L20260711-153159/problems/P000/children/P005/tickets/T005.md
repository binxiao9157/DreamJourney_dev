# 将家庭知识授权边界设为默认发布门

## Problem Definition

新增 authority、repository、Echo 与 sync/import gates 尚未全部纳入默认 release regression/release QA，canonical 与状态矩阵也未形成可交接证据；后端现有 accepted viewer policy 需要 targeted regression 证明未被客户端改动误解。

## Proposed Solution

把四个新 runner 与扩展后的 context/merge model 设为默认 release steps，并由 release-qa-package-check 强制文件/命令存在。更新 canonical、PRD coverage、release matrix 和 Task 状态。运行后端 Context/family targeted tests、release QA、完整 release regression、Simulator/generic iPhoneOS build、diff check；按实际差异判断后端是否需要部署。

## Acceptance Criteria

- 默认 release regression 无开关地运行四个新 gates。
- release QA package 强制文档、runner 和 smoke source 存在。
- 后端 pending/accepted/revoked family Context targeted tests 通过。
- release QA、完整 regression、Simulator/generic iPhoneOS build 与 diff check 通过。
- 文档明确后端是否变化/部署、真机与产品保留边界。
- iOS 提交推送，工作区与远端一致。

## Verification Plan

先运行新 gates 和 release-qa-package-check，再运行 backend pytest selectors、release regression、generic iPhoneOS build；检查 git diff/secrets，提交推送并记录 report path。

## Risks

- 全量 regression 时间较长，旧 static guard 可能仍断言不安全默认；应更新过时断言而不是恢复旧行为。
- 后端仓库存在非本任务未提交改动时不得混入或部署。

## Assumptions

- 本轮 iOS 行为改动不需要后端 schema/route 变化。
- 不执行真机和服务器部署，除非审计确认后端存在本任务必要差异。
