# 将 FamilyRepository 改为账号绑定的后端关系仓库

## Problem Definition

现有仓库无 owner/generation，自动把 KBPerson 和启动 mock 加入 members，并使用跨账号全局 override；迟到后端响应和旧成员可跨登录状态残留。

## Proposed Solution

FamilyRepository 初始化并监听当前账号，使用 owner + UUID generation 管理内存状态；登录/退出清空并重新加载 owner-scoped overrides。后端 refresh 只接受匹配 owner 的 backendInvitation records 并权威替换；invite/refresh 回调捕获 generation。KBPerson 只投影到独立 candidate 列表。移除 release mock，UIQA fixture 显式 source/owner。

## Acceptance Criteria

- knowledgeCandidates 与 members 分离，KB 更新不 append member。
- active owner/generation 对 login/logout、refresh/invite 生效。
- remote list 权威替换且拒绝缺 owner/wrong owner。
- mode/voice override owner-scoped，更新仅限 accepted member。
- release 不 seed mock；QA fixture 显式 owner/source。
- static gate、authority smoke 与 Simulator build 通过。

## Verification Plan

运行 authority model smoke、repository lifecycle static check 和 xcworkspace Simulator Debug build；搜索旧 seed/merge/global override 模式并运行 diff check。

## Risks

- 首次进入家庭页在远端 refresh 完成前会显示真实空态，不再短暂显示 mock，这是预期。
- 迟到请求 completion 返回 stale error，调用 UI 必须保持已有失败处理。

## Assumptions

- UserManager login/logout 通知是账号生命周期权威事件。
- 后端 family list 是当前 owner 的权威集合。
