# 让持久化角色与 Echo Context 使用 accepted family preflight

## Problem Definition

relation-only personal 推断、未复核的持久化 family context 与 Echo backend request 可绕过 repository authority，使旧/伪造角色开启 personal fallback 或请求未授权 family persona。

## Proposed Solution

移除 relation-only personal 判定；KBLiteManager 增加 optional authorized identity resolver，family 必须命中当前 repository accepted member。DigitalHumanContextStore 改为 user-scoped key，get/set 都验证 member，失败回退 self。Echo 建 gate 和发 `/context/build` 前使用 optional resolver，失败记录明确 fallback，不发请求；family 请求带 member ID。

## Acceptance Criteria

- relation="本人" 不能把 family owner 变 personal。
- explicit self/owner-viewer exact match 保持 personal。
- persisted invalid family context 回退 self。
- Echo unauthorized family 不建请求，accepted family 使用 canonical digitalHumanId。
- family request 传 viewerFamilyMemberID，后端可复核 accepted 状态。
- model/static smoke 和 workspace build 通过。

## Verification Plan

扩展 knowledge context model smoke；新增 Echo family context static gate；运行 Simulator workspace build 和现有 family/context 后端测试。

## Risks

- 旧全局 context key 不再读取，用户会回到 self，而不是恢复未经验证角色，这是预期安全迁移。
- family member 在对话中被撤销时，当前 turn context 将被丢弃，不应降级使用个人知识。

## Assumptions

- current user owner 调用 family persona 时，viewerFamilyMemberID 使用被选择的 accepted member ID，后端 policy 会再次校验。
