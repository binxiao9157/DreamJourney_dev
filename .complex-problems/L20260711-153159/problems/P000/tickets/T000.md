# 实施家庭授权与知识候选隔离的 P0 闭环

## Problem Definition

当前 iOS 将 `KBPerson` 自动转换为默认 `active + accepted` 的 `FamilyMember`，FamilyRepository 又缺少账号 generation 和 owner 分区；relation 文本、持久化 digital-human context、通用 knowledge sync 与无签名本地分享包形成多条权限旁路。后端已把 accepted 手机号邀请作为 Context 授权来源，但客户端没有在列表、Echo 和同步入口统一消费，可能让知识候选、legacy 数据、前一账号成员或伪造 JSON 获得家庭知识权限。

## Proposed Solution

以后端手机号邀请 accepted 合同作为唯一生产家庭关系 authority，建立纯 `FamilyRelationshipAuthorizationPolicy`，统一收敛 FamilyRepository、Echo identity/context、knowledge sync 与 legacy family share。FamilyMember 明确 owner/source，legacy/default deny；KBPerson 只进入候选集合；FamilyRepository 使用 active owner/generation 和 owner-scoped overrides；Echo 与持久化 context 在请求前复核 accepted member；sync 拒绝 wrong-owner/ownerless/unaccepted-family；本地整库导入默认关闭。任何 KBPerson、legacy、本地默认、旧账号响应或无签名数据都不能提升为家庭权限。

## Acceptance Criteria

1. FamilyMember 模型包含 owner 与 authority source，legacy/local/default fail closed；仅当前 owner 的 backendInvitation + active + accepted 可用于生产家庭业务。
2. KBPerson 仅进入独立候选集合，不进入成员列表或 Echo/收件人/音色/care。
3. FamilyRepository 绑定账号 generation，切换/登出清理，迟到响应拒绝，mode/voice override 按 owner 分区。
4. relation 文本不能单独把非 self context 推断为 personal；持久化 family context 和 Echo family 请求必须重新验证 accepted member。
5. knowledge sync 拒绝 wrong-owner、ownerless legacy 上传和未授权 family persona；本地 legacy 兼容不能变成远端/生成权限。
6. 裸 graph 与无后端 grant 的 share package 默认拒绝，不显示伪成功。
7. 后端 pending/failed/revoked family Context 保持 fail closed，accepted exact-match 正常通过。
8. 新增模型、静态与组合 gates，接入默认 release regression/QA；Simulator 和 generic iPhoneOS build 通过。
9. iOS 与后端各自按实际改动提交推送；若后端无需行为变化，须记录现有服务端合同和测试足以覆盖。

## Verification Plan

- 纯 Swift 模型 smoke 验证 authority 状态矩阵、relation spoof、owner/persona sync policy 和 import policy。
- 静态 gate 验证 KB candidate 隔离、账号/generation 生命周期、owner-scoped overrides、Echo preflight 和 release UI 不暴露。
- 运行现有 backend family/context 单测与 smoke，证明 pending/revoked 拒绝和 accepted 放行。
- 运行 release QA package、完整 release regression、Simulator Debug build、generic iPhoneOS no-sign build、`git diff --check`。

## Scope Boundary

- 不新增公开候选转家人 UI，不实现解除关系，不开放整库分享，不改 Stitch UI，不做真机。
- 不重写后端 Context Builder；优先复用现有 accepted viewer policy。

## Risks

- 现有启动 mock 和 legacy 本地成员会从默认 accepted 变为未授权，若 QA 未显式标记会导致旧 smoke 失败，需要同步修正测试 fixture，而不能恢复不安全默认值。
- FamilyRepository 是全局单例，账号 generation 改造必须防止 refresh/invite 回调竞态和通知重入。
- 禁用本地整库导入可能改变隐藏知识页行为，但这是在没有服务端授权合同前的必要 fail-closed 边界。

## Assumptions

- 后端 family member payload 的 `ownerUserId/userId`、`accessStatus` 和 `invitationStatus` 是唯一生产关系授权事实。
- QA fixture 可通过编译/launch 策略显式放行，但不能进入 release 授权判断。
- 本轮允许保留 ownerless legacy 知识在当前用户本地浏览，但不允许上传、跨 persona 生成或转为家庭权限。
