# 实现 iOS Proposal Schema 与 Client Envelope

## Problem Definition

iOS 模型无法表达 proposal/persona metadata，backend client 丢弃 `mutationProposal`，因此后续 manager 无法确定性合并。

## Proposed Solution

以 optional additive 字段扩展 KBLite 实体，新增独立 proposal upsert/envelope Codable 类型；修改 `extractKnowledge` 接收 persona identity、发送请求字段并返回 extraction + optional proposal。解码必须兼容旧服务端。

## Acceptance Criteria

- 旧 KBLite JSON 和旧 extraction response 继续解码。
- 完整 proposal 的 ID、relations、metadata、revision 和 policy 可解码。
- request payload 包含 canonical personaScope/digitalHumanId。
- malformed proposal 不污染 extraction 兼容路径，并产生明确解析策略。

## Verification Plan

新增独立 Swift model smoke 和静态 source check，并运行相关脚本、diff check 与编译。

## Risks

- 新字段若使用 nonoptional 会破坏旧 JSON；必须使用 optional/default-safe 解码。

## Assumptions

- manager 合并逻辑由后续 P006 消费 envelope。
