# 实现 iOS Identity-bound Proposal 合并与 Persona 本地策略

## Problem Definition

KBLiteManager 尚未消费 proposal，异步提取只绑定用户 generation；existing summary、quick extraction 和 local generation fallback 也可能跨 persona 读写。

## Proposed Solution

引入轻量 `KBPersonaIdentity` 与纯策略，统一从当前 DigitalHumanContext 解析 canonical identity。提取请求捕获 identity，使用 envelope；completion 同时校验用户 generation 与当前 identity。proposal-first merge 先建立 proposal-to-local ID remap 再合并实体/关系；legacy extraction/quick fallback 继续工作但写入 identity metadata。summary 和 local generation 按 personal-legacy/family-strict 过滤。

## Acceptance Criteria

- proposal merge 不重复本地 natural match，关系 remap 有效。
- entity metadata/source/evidence 持久化，candidate 仍不进入 generation。
- user/persona 切换旧回调被丢弃。
- personal legacy 可用；family 只读写显式匹配实体。
- old extraction/server/local graph compatibility 保持。

## Verification Plan

新增纯 Swift persona/merge smoke 或 test hook、静态 source guard，跑 proposal/context/three-way smoke 和 generic builds。

## Risks

- KBLiteManager 较大，修改必须集中在 extraction/merge/context 路径，避免无关重构。
- local legacy ID remap 必须在关系合并前完成。

## Assumptions

- family digitalHumanId 从 FamilyRepository canonical 字段获取，缺失时使用 ownerId 与 Echo 现有策略一致。
