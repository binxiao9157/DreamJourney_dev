# 收敛 Knowledge Proposal/Persona 跨仓库 QA 与交付

## Problem Definition

后端和 iOS 功能已分别实现，但新合同尚未作为 release regression 常态 guard，也缺最终状态文档、全量构建证据和独立提交。

## Proposed Solution

新增后端 proposal/persona smoke runner，将 iOS proposal model 与 persona source guard 接入 release regression/release QA package；运行后端全量 verify、知识 gates、release regression、generic Simulator/iPhoneOS build 和 diff checks；更新 canonical/status/Lodestar 后分别提交两仓库。

## Acceptance Criteria

- 日常 release regression 始终运行 iOS proposal model 与 static policy guard。
- 可选跨仓库 gate 可运行后端 proposal/context persona tests，不依赖部署环境。
- 后端 212+ tests、iOS release regression、generic Simulator/iPhoneOS build 通过。
- 状态文档准确记录实现、验证、非真机边界和后续任务。
- 两仓库干净且各有清晰提交；不推送、不部署。

## Verification Plan

执行所有新增/既有知识 gates、`verify_backend.sh`、release QA package、release regression、generic builds、closure check 和 git diff/status。

## Risks

- release regression 体量较大；新增 guard 必须快速、确定、无外部网络依赖。

## Assumptions

- 当前目标明确不要求推送、部署或真机。
