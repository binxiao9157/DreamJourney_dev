# 实现后端 Knowledge Mutation Proposal Builder

## Problem Definition

`/kb/extract` 的 provider extraction 没有稳定 ID、revision、persona metadata 或关系 ID，客户端无法在重试和多端环境中确定性合并。

## Proposed Solution

新增独立 `knowledge_proposal` 服务，规范化 persona 和自然键，从 `get_kb_snapshot_record` 建立现有实体索引，复用 legacy ID 或生成确定性 SHA-256 ID，填充来源、隐私、证据状态和关系 ID，并由 `/kb/extract` v2 additive 返回 proposal。

## Acceptance Criteria

- proposal schema/revision/upserts 可直接通过 Mutation V2 validator。
- 重试生成相同 ID，existing snapshot ID 优先复用。
- 关系解析只指向有效 ID，未知关系被省略。
- metadata 经过净化且不包含 transcript 正文。
- dryRun 不调用 provider，也不伪造 proposal。

## Verification Plan

运行 proposal 纯函数测试、endpoint mocked provider 测试、现有 evidence tests 和后端全量 unittest/verify。

## Risks

- 同名实体消歧有限；使用保守自然键并记录后续治理边界。
- snapshot revision 可能在 proposal 后变化；由既有 Mutation V2 409 处理。

## Assumptions

- snapshot record 是现有实体与 revision 的权威来源。
- proposal 只建议 upsert，不执行持久化或删除。
