# 实现后端 Persona-scoped KB Context Policy

## Problem Definition

Context Packet 当前对 KB facts 仅执行 personal-self 粗粒度开关；family facts 无法使用，而 `memory.kbFacts` 与 generation candidate 也可能采用不同筛选口径。

## Proposed Solution

建立实体级 persona 判定：personal 兼容无 metadata 的旧事实但拒绝显式其他 persona；family 必须 owner、scope、digitalHumanId 全匹配。候选、memory summary、filtered reason 和 generation selection 复用同一判定，并继续叠加 privacy、confidence/evidenceStatus 门禁。

## Acceptance Criteria

- personal legacy fact 可用；显式 family/mismatch personal fact 被过滤。
- family matching fact 可用；legacy、owner/scope/digitalHuman mismatch 被过滤并有固定 reason。
- candidate、memory.kbFacts 和 generationContext 保持一致。
- candidate/low confidence 仍不能进入 generation。

## Verification Plan

新增 Context builder 单元测试并运行 context v2 smoke、全量后端测试、py_compile 和 diff check。

## Risks

- 旧 family 数据缺 metadata 时不可用，这是有意的安全默认。
- `ownerUserId` 表示当前 KB 账号 owner，不代表被提及人物或家庭成员授权身份。

## Assumptions

- family request 已使用 canonical digitalHumanId。
- KB entity 不能自行授予 family relationship 权限。
