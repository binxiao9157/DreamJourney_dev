# 移除 App 生产路径的全局时间信件调度

## Problem Definition

App 刷新 mailbox 时仍调用 system-only 的 `/archive/time-letters/dispatch-due`，与服务器 timer 重复且会被新的 principal-bound policy 拒绝。

## Proposed Solution

- 修改 `MemoryArchiveRepository.refreshTimeLetterMailboxReminders`，直接获取当前用户 mailbox。
- 保留 backend client 的 dispatch 方法供 QA/system tooling 使用，但不在公开 App 业务路径调用。
- 更新时间信件静态检查，固定“客户端只读 mailbox、服务器负责 dispatch”的边界。

## Acceptance Criteria

- mailbox refresh 不再发起 dispatch-due。
- 时间信件 reminder 拉取、已读、归档逻辑不变。
- 静态 QA 与相关 smoke 通过。

## Verification Plan

- 搜索生产 repository 的 dispatch 调用为 0。
- 运行时间信件 delivery/lifecycle/message center 检查。
- 运行相关 iOS 构建与 `git diff --check`。

## Risks

- 如果服务器 timer 停止，客户端不再兜底投递；线上 timer 已确认 active，应由 readiness/部署监控负责。

## Assumptions

- 服务端 dispatch timer 每分钟运行。
- reminder mailbox GET 是当前 App 的唯一消费入口。
