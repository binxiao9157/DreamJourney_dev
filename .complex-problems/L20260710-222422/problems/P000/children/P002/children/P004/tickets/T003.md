# 接入注册表并强制 principal-bound 决策

## Problem Definition

后端已有完整 route registry，但 user bearer 的 owner mismatch 和 system-only 调用仍只受全局 shadow/enforce 控制，不能形成安全边界。

## Proposed Solution

- 扩展授权策略决策，标记 `principal_bound`。
- 由注册表解析 ownerBody/ownerPath 并比较登录 principal。
- owner mismatch 与 system-only user 调用在 shadow 模式下也立即 403。
- public/service/userSession/delegated 分别保留现有语义，legacy backend token 继续优先通过。
- 扩展 auth integration tests 覆盖代表性业务路由与委托访问回归。

## Acceptance Criteria

- owner 与 system-only 的非法 user 请求返回 403。
- owner 自身、delegated 和 system token 正常。
- 全局 ownership mode 仍是 shadow。
- 拒绝日志不含原始用户信息和 token。

## Verification Plan

- 运行 route ownership、authorization policy、auth sessions、cross-account 全套单测。
- 增加多路由 owner path/body 参数化测试。
- 运行 `git diff --check`。

## Risks

- 通用规则若先于 delegated 规则执行，会误拒绝合法家庭访问；实现中必须让专用 delegated policy 优先。

## Assumptions

- backend token 保持 system principal 兼容通道。
- 未带 user token 的本地 memory 测试继续沿用现有兼容行为。
