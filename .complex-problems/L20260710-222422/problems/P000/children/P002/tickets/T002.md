# 将路由 ownership 注册表接入 principal 强绑定

## Problem Definition

当前用户 bearer 已能识别 principal，但大多数 owner mismatch 只记录 shadow 日志，不会阻止跨用户访问；同时 iOS mailbox 刷新还会触发属于服务端职责的全局时间信件扫描。

## Proposed Solution

- 在 `CrossAccountAuthorizationPolicy` 中消费 `RouteOwnershipRegistry`。
- ownerBody/ownerPath 路由在 user principal 与 owner 不一致时直接拒绝，一致时明确放行。
- systemOnly 路由拒绝 user principal；legacy system token 继续由现有中间件优先放行。
- delegated family/time-letter/invitation/care 继续走既有委托策略，不改产品合同。
- 中间件仅对 principal-bound 决策立即 403；全局 `AUTH_OWNERSHIP_MODE` 继续保持 shadow，不开启未知路由的全局 enforce。
- iOS mailbox refresh 只拉取 mailbox，不再调用 `/archive/time-letters/dispatch-due`，交由现有服务器 timer 执行。

## Acceptance Criteria

- user bearer 跨 owner 访问代表性 ownerBody/ownerPath 路由返回 403。
- user bearer 调用 systemOnly 返回 403，即使全局模式为 shadow。
- owner 自身访问、委托访问和 backend system token 不回归。
- iOS 生产刷新路径不再调用全局 dispatch-due。
- 授权日志只记录 hash，不输出 phone、token 或原始 user id。

## Verification Plan

- 扩展后端 auth session 集成测试，覆盖 profile、archive、mailbox、voice、KB、digital-human session、push、echo、family 和 system dispatch。
- 运行现有 cross-account policy 与 auth session 全套测试。
- 新增/更新 iOS 静态检查，确认 repository 不再触发 dispatch-due。
- 运行 `git diff --check` 和相关 Swift QA 检查。

## Risks

- 旧客户端如果用 user token 操作其他 userId，会从 shadow 日志变为 403；这是预期安全收紧，但需由覆盖测试确认当前 iOS 均使用登录用户 id。
- delegated 路由不能被通用 owner 规则覆盖，否则会破坏合法家庭访问。

## Assumptions

- 线上 systemd timer 已启用并每分钟调用时间信件 dispatch。
- backend token 是服务间 system principal 的兼容入口。
- 全局 ownership enforce 暂不启用。
