# 新增 Ownership 静态与部署 Smoke Gate

## Problem Definition

当前测试分散，release QA 无法一键证明 route registry、principal-bound 规则、客户端 system 边界和部署 HTTP 行为同时成立。

## Proposed Solution

- 新增 `route-ownership-audit-check.swift` 跨仓库检查实现边界。
- 新增 `backend-route-ownership-audit-smoke.py` 与 shell wrapper，使用两名临时用户验证 owner 正向、跨 owner/system 403 和 runtime audit。
- 输出仅含固定状态、计数和 hash 的 JSON 报告。
- 在 release regression 添加 `RUN_BACKEND_ROUTE_OWNERSHIP_AUDIT_SMOKE=1` 可选开关。
- 更新 QA README 和 Task 11 状态。

## Acceptance Criteria

- 静态 check 与本地 HTTP smoke 可重复通过。
- 脚本不输出 token、手机号、昵称或原始 user id。
- release 默认不依赖部署后端，开启开关时执行 smoke。
- 后端全测和 iOS generic build 通过。

## Verification Plan

- 运行 Swift check、Python compile、memory/local HTTP smoke。
- 运行后端全量测试、`git diff --check`、generic Debug build。

## Risks

- 脚本需复用私密 access 文档读取方式，不能把 token 写入仓库或命令输出。

## Assumptions

- 现有 auth/cross-account smoke 提供可复用的 URL/token 解析与脱敏模式。
