# 实现用户会话与 ownership shadow 小闭环

## 目标

在不破坏现有 `BACKEND_API_TOKEN` 客户端和服务端任务的前提下，为登录用户建立可刷新、可撤销、可审计的 opaque 会话，并让 iOS 通过 Keychain 安全消费；服务端仅以 shadow 模式观察 userId 声明不一致，不立即阻断业务。

## 实现范围

- 后端内存/Postgres auth session 存储与 token hash 边界。
- 登录签发、refresh 旋转、logout 撤销、过期/撤销校验。
- 中间件同时支持 legacy backend token 与 user bearer principal。
- ownership shadow 采集、脱敏日志和 QA 响应头。
- `/config/runtime` 能力合同。
- iOS Keychain store、登录保存、请求头、一次自动刷新和退出清理。
- 后端测试、iOS 静态 guard、模拟器 smoke、release gate。

## 验收标准

- 数据库不保存 access/refresh 原文。
- refresh token 单次消费并旋转；旧 token 不可重放。
- logout 后 access token 失效。
- backend-token-only 旧请求继续通过。
- shadow mismatch 可观察但请求仍成功。
- iOS 不把 token 写入 UserDefaults，不发生递归刷新。
- 后端全量测试、iOS build、模拟器和 diff check 通过。

## 验证计划

- 后端 API/store 单测覆盖签发、解析、过期、旋转、撤销、兼容和 shadow。
- Postgres fake/store 测试覆盖唯一 token hash 与原子 refresh 消费。
- Swift 静态检查覆盖 Keychain、双 header、refresh retry 和 logout。
- 模拟器登录 smoke 验证 auth 保存、授权请求、强制 refresh 和清理。
- release regression 使用可选开关组合运行，且不需要真机。
