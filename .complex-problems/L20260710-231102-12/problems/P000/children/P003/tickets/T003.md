# Context Packet 驱动真实 Echo 生成

## Problem Definition

现有 `/context/build` 只生成 Context V2 trace，真实 Echo 回复仍依赖会话启动时注入的本地最近摘要，因此后端 policy、ranking、ownership 过滤结果不影响回答，也存在重复注入和跨用户异步污染风险。

## Proposed Solution

后端为现有 Context Packet 增加兼容的 `generationContext` 字段，只汇总通过 policy 的 archive、KBLite fact、persona、care 内容，并提供来源、稳定哈希和长度边界。iOS 在最终 ASR 后请求 Context Packet，通过火山 Dialog SDK 的 `SEDirectiveEventChatRagText` 为当前 turn 提交一次上下文；后端超时或失败时按当前 query 使用当前用户的 KBLite 检索降级。使用 lifecycle/turn gate 丢弃过期回调，并在启用 turn-scoped RAG 时停止会话启动阶段的旧知识摘要注入。

## Acceptance Criteria

- `/context/build` 返回稳定、长度受限、可追踪来源且哈希可复现的 `generationContext`。
- 草稿或未到期时间信件、失败图像空线索、无效家庭数据等被过滤内容不进入生成文本。
- iOS 正常路径将后端 `generationContext.text` 送入 `SEDirectiveEventChatRagText`，每个 turn 最多一次。
- 后端失败或超时后使用 `KBLiteManager.buildContextString(query: 当前用户文本)`，不使用无 query 的全量摘要。
- lifecycle token、turn ID 或用户变化后，异步结果被丢弃。
- 旧启动 prompt 不再重复注入知识上下文，现有 Context V2 trace/evidence 保持兼容。

## Verification Plan

运行后端 Context Packet 单测和 smoke，覆盖 policy、稳定哈希、长度和兼容字段；运行 iOS 静态 QA 检查，覆盖 RAG 指令、超时降级、query-based KBLite、单次提交和旧注入移除；最后运行 `git diff --check`、后端全量测试、release QA、generic iOS Simulator 与 iPhoneOS build。

## Risks

- 火山 SDK 的 RAG 指令必须在当前 query 等待窗口内到达，因此需要短超时和单次提交 gate。
- 后端延迟可能导致本轮使用本地降级，但 trace 仍需保留以便诊断。
- Context 文本过长会增加响应延迟，必须在后端统一截断。

## Assumptions

- 当前 SpeechEngineToB 版本已声明并支持 `SEDirectiveEventChatRagText`。
- `/context/build` 已完成 Context V2 ownership 和 policy 过滤。
- 本轮不改变公开 UI、数字人音频 owner、声音复刻或延迟回信状态机。
