# iOS 每轮 Echo RAG 注入

## Problem Definition

Echo 对 `/context/build` 的调用只写 trace，火山 Dialog 回复仍使用启动时旧摘要，无法消费当前 query 的后端 policy/ranking 结果，且存在旧摘要重复注入和异步回调跨 turn 污染风险。

## Proposed Solution

扩展 EchoContextPacket 解析 generationContext；让 Echo 最终 ASR 后创建一次性 turn gate，并在 0.9 秒内优先把后端文本通过 `SEDirectiveEventChatRagText` 发送给当前 SDK query。超时、失败或旧服务器缺字段时按当前 query 使用本地 KBLite。用 lifecycle token、turnID、userID 与单次提交标记阻止过期/重复注入。Echo 启动 Dialog 时启用 turn-scoped 模式，生产引擎不再附加旧 KBLite/档案摘要。

## Acceptance Criteria

- generationContext 字段完整解析且旧服务器响应仍可处理。
- 当前 turn 最多提交一次 ChatRagText。
- 后端失败、超时和缺合同均使用 query-based 本地降级。
- 生命周期、用户或 turn 变化后旧回调不会提交。
- 延迟回信不触发生成 RAG，已有 trace 仍记录。
- 旧启动知识摘要不与 turn RAG 重复，非 Echo 调用保持默认行为。

## Verification Plan

运行 knowledge pipeline、Context Packet、Dialog/archive 静态检查，generic Simulator build、generic iPhoneOS build 和 release regression；检查编译警告与 git diff。

## Risks

- SDK ChatRagText 的在线时序仍需后续真机观测，本轮通过 SDK 声明、编译与 QA gate 固定调用合同。
- 0.9 秒超时会在弱网时更多使用本地知识，但不会阻塞对话。

## Assumptions

- SpeechEngineToB 当前版本声明 `SEDirectiveEventChatRagText`。
- 后端 generationContext 已完成安全筛选。
