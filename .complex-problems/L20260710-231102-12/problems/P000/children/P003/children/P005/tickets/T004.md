# 后端生成上下文合同

## Problem Definition

Context Packet 只有 selected/filtered/ranking 调试结构，没有可直接交给 Echo 生成引擎的稳定文本；如果由 iOS 自行拼接，会重复后端 policy 并产生隐私与一致性风险。

## Proposed Solution

在 ContextPacketBuilder 基于最终 selected candidates 构建 additive `generationContext`，提供版本、长度受限文本、来源引用/计数、稳定内容哈希及截断状态。仅渲染允许 AI 处理的 archive/KBLite fact/persona/care 内容，不读取 runtime voice/digital-human 字段。

## Acceptance Criteria

- 现有 `/context/build` 字段完全兼容并新增 generationContext。
- 被过滤或未授权内容不会进入文本。
- 相同输入生成相同文本和哈希，空输入合同稳定。
- 长文本受统一上限约束并标记 truncated。
- Context V2 单测与 smoke 通过。

## Verification Plan

运行 Context Packet 聚焦单测、Context V2 smoke、Python 编译检查和 `git diff --check`。

## Risks

- 旧 KBLite 数据缺少 privacy metadata 时必须默认不进入生成。
- 文本格式变化会影响哈希，因此版本需要固定。

## Assumptions

- selectedContext 已完成 ownership、timeLetter、family 与分析状态 policy。
- generationContext 为 additive 合同，不替代 trace。
