# 后端知识增量合同实现结果

## Summary

在不破坏旧 snapshot/ContextPacketBuilder 读取方式的前提下，为 InMemory/Postgres 增加了可审计、幂等的 P0 知识增量同步层。

## Done

- 新增 `KnowledgeRevisionConflict`，统一表达 stale base revision。
- InMemory/Postgres store 新增 `apply_kb_mutation`、`get_kb_snapshot_record`、`list_kb_changes`。
- `kb_snapshots` 增加 revision；新增 `kb_changes`、operationId 唯一约束和 user/revision 索引。
- Postgres mutation 使用用户级 advisory transaction lock、operationId 查重和 snapshot row lock，保证并发幂等。
- `/kb/sync` 保持兼容并新增 revision；snapshot 响应增加 revision/updatedAt。
- 新增 owner-bound `/kb/mutations` 与 `/kb/changes/{user_id}`，并纳入 route ownership registry。
- 新增 knowledge delta smoke 并接入 `verify_backend.sh`。

## Verification

- `scripts/verify_backend.sh` 通过。
- 180 个后端 unittest 通过。
- FastAPI health/runtime smoke 通过。
- `scripts/run-backend-knowledge-delta-smoke.sh` 通过。
- Postgres fake-store 持久化、幂等、change feed、冲突测试通过。
- `git diff --check` 通过。

## Known Gaps

- 尚未部署到线上 Postgres；本任务范围先完成代码和本地合同验证。
- P0 mutation 使用经过隐私过滤的整图 replacement，不提供通用 JSON Patch 或实体级冲突合并。
- change retention/compaction 与 pgvector 不在本任务范围。
