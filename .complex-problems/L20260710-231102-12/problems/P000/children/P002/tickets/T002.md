# 为 KBLite 增加按用户生命周期、自动同步与 backend-first extraction

## Problem Definition

KBLiteManager 的 graph 在单例初始化时加载，文件路径虽按当前用户计算，但进程内用户切换不会重新加载；对话提取直接调用 DeepSeekService；后端 `syncKnowledge` 无业务触发点。需要在保持现有知识 UI、JSON 文件和本地语义检索的前提下消除隔离与同步缺口。

## Proposed Solution

给 KBLiteManager 增加显式 `switchUser(to:)`、当前加载 user ID、变更通知和 backend-first extraction 注入点；新增 `KnowledgeSyncCoordinator` 串行管理 mutation/change-feed/snapshot 兼容降级、revision 和去重；扩展 DreamJourneyBackendClient 的 extract/mutate/changes 合同。UserManager 登录/恢复/登出调用切换，App 前台和提取完成触发同步。后端不可用时仅调用现有本地规则提取，并记录 fallback reason；不再从 KBLite 主链路调用客户端 DeepSeek。

## Acceptance Criteria

- 用户 A/B 进程内切换不会共享内存 graph，登出后为匿名隔离文件或空图谱。
- 同步协调器串行、去重并保存每用户 revision；新后端走 mutation/changes，旧后端可回退 snapshot sync。
- 正常知识提取调用 `/kb/extract` 并合并结构化结果；失败时本地规则提取仍可完成。
- 提取完成、用户切换和前台恢复均有稳定同步触发点，且不会递归触发无限同步。
- 不改现有知识库公开 UI，KBLite 搜索/导出和 ConversationMemoryManager 调用兼容。

## Verification Plan

增加 Swift 静态 guard 或 launch-arg smoke，覆盖 A/B graph 隔离、backend-first 路由、fallback、revision 保存和触发点；运行相关现有脚本、release regression、`git diff --check` 和 generic iPhoneOS build。

## Risks

- UserManager 当前登录恢复路径较多，遗漏一个切换点会保留旧 graph。
- backend extraction JSON 与现有 KBLite extraction decoder 可能字段不完全一致。
- 前台同步不能阻塞主线程或在无认证会话时产生噪音请求。

## Assumptions

- P0 继续使用每用户 JSON 文件和 UserDefaults revision，不迁移数据库。
- graph mutation 先整图发送，实体级 merge 留给 P1。
- 现有本地 regex 提取可作为离线 fallback。
