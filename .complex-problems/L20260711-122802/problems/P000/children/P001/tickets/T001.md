# 在知识 mutation 入口 canonicalize 隐私 metadata

## Problem Definition

`normalize_kb_mutation_v2` 输出仍含客户端 source title，导致 payload hash、change、receipt 和 response 与已过滤 graph 不一致。

## Proposed Solution

在 privacy service 暴露知识实体 source-ref canonicalizer，并让 `normalize_kb_mutation_v2` 返回已经 canonicalized 的 mutation。InMemory/Postgres store 只使用这一个 normalized mutation 进行 fingerprint、apply、change/receipt 持久化和响应；不在各层重复处理。增加 raw sentinel、重放和 payload conflict 测试。

## Acceptance Criteria

- mutation upserts 的 source title 始终来自服务端 kind 映射。
- 规范化发生在 fingerprint 前。
- response/change/receipt/replay mutation 字节语义一致且无 raw sentinel。
- 只改 title 不冲突，改变 source kind/id 或正文仍冲突。
- 后端定向及全量测试通过。

## Verification Plan

新增 knowledge_store 单测、InMemory API/receipt 测试和 Fake Postgres 持久化断言；运行专用 smoke 与 `verify_backend.sh`。

## Risks

- 不能用完整 graph filter 处理局部 mutation，否则可能错误删除引用到既有实体的关系 ID。
- 必须保留 source kind/id 和所有非 title 业务字段。

## Assumptions

- source title 是展示辅助 metadata，不属于 operation 的可信用户语义。
