# 增加知识隐私组合 gate 并发布双仓提交

## Problem Definition

当前 release regression 会运行后端全量测试，但没有一个命名明确的 Task 20 gate 来证明 raw source title 在 response/change/receipt/replay 中不可见、maintenance 默认 dry-run 且报告脱敏。状态文档和 QA package 也无法防止维护入口被改成默认写入。

## Proposed Solution

- 后端新增一个只使用 Fake Postgres/memory fixture 的 knowledge privacy maintenance smoke runner，复用定向 unittest，不接生产数据库。
- iOS QA 目录新增跨仓静态 guard 和组合 shell gate，检查后端 canonicalizer、维护 CLI 默认行为、receipt hash 边界、测试 sentinel，以及 release/docs 接线。
- release regression 默认运行纯本地跨仓 guard；额外开关运行完整 maintenance smoke，绝不自动执行线上 `--apply`。
- 更新 release QA package、Task 20 与状态文档，明确生产只能手工按备份确认后的 dry-run/apply/dry-run 执行。
- 运行完整后端验证、release regression、generic iPhoneOS build；Simulator smoke 依现有 release runner 执行并保存报告。
- 审核 diff 后分别提交、推送后端 main 与 iOS 当前功能分支。

## Acceptance Criteria

- 新 gate 能因缺少 canonicalization、默认 dry-run、事务回滚测试或 release 接线而失败。
- release regression 默认不包含任何生产维护写操作；`--apply` 只存在于手工维护 CLI/文档。
- release QA package 检查新 gate 和状态文档存在。
- 后端 verify、release regression、generic iPhoneOS build、diff check 全通过；不做真机。
- 两仓提交内容只包含 Task 20 代码、QA、账本和文档，并成功推送。

## Verification Plan

- 直接运行新跨仓 gate与 maintenance unittest runner。
- `./scripts/verify_backend.sh`。
- `RUN_IPHONEOS_GENERIC_BUILD=1` 的 release regression；保留生成报告路径。
- `swift release-qa-package-check.swift` 和双仓 `git diff --check`。
- 提交后核对本地 HEAD、远端 tracking branch 与 clean status。

## Risks

- release regression 很大，历史视觉证据可能缺失；需要区分真实代码失败与既有可选证据缺口。
- macOS 大小写不敏感路径可能掩盖 CI 路径问题；新增脚本统一使用仓库既有 `Scripts/QA/prd-stitch-ui` 约定。

## Assumptions

- 后端仓库位于 iOS 同级 `DreamJourneyBackend`，也允许用 `BACKEND_ROOT` 覆盖。
- Simulator 与 Xcode 当前可用；若 Simulator 基础设施失败，仍需修复或明确报告，不能跳过 generic iPhoneOS build。
