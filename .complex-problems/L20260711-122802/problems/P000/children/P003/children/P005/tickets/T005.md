# 部署 Task 20 并安全清洗生产知识隐私 metadata

## Problem Definition

后端 `e1f06a8` 已推送，但服务器仍运行旧版本，真实 Postgres 中也可能保留 raw source title。必须在不泄露生产内容的前提下完成部署、备份、dry-run/apply/dry-run 和线上新写入 sentinel 验收。

## Proposed Solution

1. SSH 到服务器，核对后端仓库/容器/数据库健康和当前版本；使用服务器私密 `.env`，不输出 token。
2. 拉取 `origin/main` 的 `e1f06a8`，重建并重启 API，确认 `/health` 为 production/Postgres。
3. 在 apply 前使用 `pg_dump` 对知识三表及其依赖 schema 创建带时间戳备份，记录文件路径、权限、大小和校验值，不读取/打印内容。
4. 在 API 容器相同私密环境中运行 maintenance 默认 dry-run，将 stdout 保存为权限 600 的聚合 JSON；要求 `invalidRecordCount=0`。
5. 仅在 dry-run 合格后执行 `--apply`，再运行 post-apply dry-run；要求最终所有 changed=0。
6. 使用私密 backend token 创建隔离 QA 用户和 sentinel V2 mutation，验证首次响应、change feed、duplicate receipt replay 全部 canonical 且不含 raw title；证据只输出布尔值和计数。
7. 更新 iOS 状态文档/账本，提交并推送最终文档收敛。

## Acceptance Criteria

- 服务器代码与容器版本为 `e1f06a8`，health 为 production/Postgres。
- apply 前存在可读但非公开的 Postgres 备份，权限受限，校验值已记录。
- pre-dry-run、apply、post-dry-run 均成功且只输出脱敏聚合；pre-dry-run 无 invalid records，post-dry-run changed 全 0。
- 线上新 mutation 的 response/change/replay 不含 raw sentinel，canonical mutation 一致，raw/canonical 同 operation ID 重试幂等。
- 不在聊天、Git、日志报告中暴露 token、用户/source/entity ID 或知识正文。
- 最终 iOS 文档/账本提交推送，两个仓库工作区干净。

## Verification Plan

- `ssh miao-server` 核对 git SHA、Docker compose 状态与 health。
- `pg_dump` 成功、备份文件 `test -s`、`stat` 权限与 `sha256sum`。
- 容器内运行 maintenance 三阶段并用 Python 只断言 schema/mode/status/counts。
- 本地私密 token 文件驱动线上 sentinel smoke；输出红acted JSON。
- 双仓 git status、远端 tracking SHA 和最终 `git diff --check`。

## Risks

- 生产表锁会短暂阻塞知识写入；设置数据库 lock timeout，并在低流量窗口执行。
- 发现 invalidRecordCount 时必须停止 apply，不能为了完成任务跳过无效记录。
- 备份或部署环境可能与文档假设不同；先探测再操作，不覆盖服务器 `.env`。

## Assumptions

- `miao-server` SSH、sudo Docker 和 `/opt/services/dreamjourney/DreamJourneyBackend` 仍可用。
- 服务器有足够磁盘空间生成受限备份。
- 当前生产知识写入量允许一次短时维护锁；不做真机。
