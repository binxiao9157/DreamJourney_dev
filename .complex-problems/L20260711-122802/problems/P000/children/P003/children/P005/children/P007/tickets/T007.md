# 执行生产清洗并证明线上 canonical 合同

## Problem Definition

preflight 发现 4 个 change mutation、2 个 receipt result 和 2 个 V2 receipt hash 待规范，且无无效记录。需要在现有备份保护下显式 apply、证明二次 dry-run 归零，并验证部署后的新写入/重放合同。

## Proposed Solution

- 在服务器 API 容器执行 maintenance `--apply`，保存权限 600 的聚合 JSON；校验 mode/status/invalid/count schema，不输出内容。
- 紧接着运行默认 post-dry-run，要求 invalidRecordCount=0 且所有 changed=0。
- 使用本地私密 deployed access 文件读取 URL/token，不在命令输出中展示 token；调用登录与 `/kb/mutate-v2` 创建唯一 QA operation。
- 第一次发送 raw source title，再用 canonical title 和同 operation ID 重试，读取 change feed 与 replay；脚本只输出布尔值、canonical title 和计数，并在 finally 尝试清理 QA 用户或记录测试数据边界。
- 更新状态文档、Task 20 清单和账本；提交推送最终 iOS 文档收敛。

## Acceptance Criteria

- apply 聚合与 pre-dry-run 待更新计数一致或可解释，invalidRecordCount=0。
- post-dry-run 所有 changed=0。
- 首次响应、duplicate replay、change feed 与 operation replay 均不含 raw sentinel，并返回相同 canonical mutation。
- raw/canonical 同 operation ID 重试为 duplicate 且 operationPayloadVerified=true。
- 生产输出、Git 与聊天不含 token、用户/source/entity ID 或知识正文。
- Task 20 根账本完成检查，最终文档提交推送。

## Verification Plan

- 在服务器读取 apply/post-dry-run 私密 JSON并仅打印聚合断言。
- 运行受控线上 sentinel Python smoke，失败时仅显示 HTTP 状态/错误码，不显示请求凭据或知识 payload。
- 运行最终跨仓 gate、release QA、git diff check；核对远端分支。

## Risks

- apply 获得知识表锁，可能短暂阻塞写入；已有 5 秒 lock timeout，失败可安全重试且不会部分提交。
- QA 账号清理接口可能触发 30 天 soft delete 而非物理删除；测试只使用合成数据并记录边界。

## Assumptions

- P006 的备份和 dry-run 在本轮仍有效，服务器版本未变化。
- deployed access 私密文件格式可由现有 smoke 脚本解析。
