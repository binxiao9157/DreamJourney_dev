# P002 成功检查

## Summary

R001 满足 P002 的实现与非线上验证边界。维护工具覆盖 snapshot/change/receipt，默认 dry-run，显式 apply 才更新；所有 apply 更新处于同一事务，且无效记录和 SQL 中途失败都会回滚。

## Evidence

- `canonicalize_persisted_knowledge_graph`、`canonicalize_persisted_knowledge_mutation` 和 `canonicalize_persisted_receipt_result` 只规范 source title，并保留实体身份、正文、关联和额外字段。
- Postgres 入口使用独占连接、全局 advisory lock、稳定顺序的 `knowledge:{userId}` lock 和知识表锁；先完成全量扫描，再进入 apply 更新。
- 测试证明 dry-run 状态完全不变，首次 apply 清洗，第二次 apply 的所有 changed 计数为 0。
- 注入第二个数据库更新失败后，首个更新被 rollback，三类状态恢复至事务前。
- 测试证明 governance receipt hash 保持不变，V2 `kb.mutation` receipt hash 与 canonical mutation fingerprint 一致。
- 267 个后端测试、FastAPI smoke、知识 delta/V2/evidence smoke 和 diff check 全部通过。

## Criteria Map

- snapshot/change graph、change mutation、receipt result 全覆盖：成功。
- 只重算 V2 `kb.mutation` receipt hash：成功。
- dry-run 无 UPDATE、apply 幂等、异常回滚：成功。
- CLI 默认 dry-run、报告不泄露内容：成功；默认参数未设置 apply，报告结构只有模式、状态和聚合计数。

## Execution Map

- R001：维护服务、Postgres 事务入口、CLI、单元/回归测试。

## Stress Test

- 无效 sourceRefs 不被静默删除，dry-run 报 invalidRecords，apply 拒绝并回滚。
- 数据库在部分 UPDATE 后失败，验证全事务回滚。
- raw/canonical 重跑验证第二次 apply 零更新。

## Residual Risk

- 真实部署 Postgres 的锁和 JSONB 更新仍需在 P003 部署后执行 dry-run/apply/dry-run 验收；该风险没有被 P002 单元测试冒充为已完成。
