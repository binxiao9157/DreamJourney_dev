# 历史知识隐私 metadata 维护工具实现结果

## Summary

完成历史 `kb_snapshots`、`kb_changes` 与 `kb_operation_receipts` 的 source title canonicalization 工具。维护入口默认 dry-run，显式 apply 才写库；所有扫描和更新位于一个独占连接与单事务内，异常完整回滚，输出仅含聚合计数。

## Done

- 新增严格的历史 graph、mutation、receipt result canonicalizer；无效历史结构不会被静默删除或部分修复。
- 新增 `PostgresStore.maintain_knowledge_privacy_metadata(apply:)`，获取全局 maintenance lock、按稳定顺序获取用户知识锁，并锁定三张知识表后扫描。
- dry-run 不执行 UPDATE；apply 只更新发生变化的 JSONB 字段。
- 仅对 `operation_kind=kb.mutation` 且 `schema_version=2` 的 receipt 按 canonical mutation 重算 payload hash；其他 operation hash 保持不变。
- 新增默认 dry-run 的 `scripts/maintain_knowledge_privacy_metadata.py`，仅 `--apply` 允许写入。
- 新增输入不变性、字段保留、幂等重跑、无效记录拒绝和数据库中途失败回滚测试。

## Verification

- 定向维护与 store 测试：64 tests passed。
- 后端全量 `scripts/verify_backend.sh`：267 tests passed。
