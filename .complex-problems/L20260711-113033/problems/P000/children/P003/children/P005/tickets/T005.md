# 提交双仓并部署认证只读来源审计合同

## Problem Definition

本地代码、gate 和文档已验证，但远端分支和线上服务器仍未包含新来源审计 endpoint。需要完成可追踪提交、部署和真实 Postgres 合同证据。

## Proposed Solution

先检查并暂存各仓库与 Task 19 直接相关的文件，分别提交并推送 iOS 当前 feature 分支与后端 main。随后通过现有 SSH 运维流程在服务器拉取后端 main、重建 API 容器并检查 health。新增或复用部署 smoke，用临时登录用户创建 canonical 知识来源后调用 owner-bound audit endpoint，校验聚合响应、隐私边界和跨账号拒绝。

## Acceptance Criteria

- iOS 与后端各自提交内容只包含 Task 19 及其计划/ledger 状态，不夹带临时产物或凭据。
- 两仓 push 成功且本地 HEAD 与对应 origin 一致。
- 后端服务器运行新提交，health 正常且 store=postgres。
- 线上 smoke 验证 schemaVersion=1、合法计数与 recommendedAction，不返回 graph/source IDs，并拒绝其他用户访问。
- 文档记录提交、部署和报告路径；不做历史迁移和真机测试。

## Verification Plan

提交前运行双仓 diff/status；push 后比较 HEAD 和 origin。部署后读取容器/health 状态，运行认证 deployed source audit smoke，并保存脱敏 JSON/Markdown 报告。

## Risks

- 服务器目录或 compose service 名可能变化，必须先只读检查现状。
- smoke 不得输出 access token、后端 API token 或真实用户内容。
- 部署期间保留服务器 `.env`，不得覆盖私密配置。

## Assumptions

- 当前 SSH 配置和后端部署权限仍有效。
- 后端 `main` 是服务器部署分支，iOS 推送当前 `feature/prd-stitch-ui-adaptation`。
