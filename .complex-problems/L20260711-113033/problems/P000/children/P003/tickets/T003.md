# 固化 canonical 来源合同并完成双仓交付部署

## Problem Definition

后端与 iOS 已分别实现 canonical source identity，但还缺少统一可重复的跨仓验证入口、准确的知识库架构说明、release QA 防回退检查，以及线上部署后的只读审计证据。若直接提交，后续修改可能重新生成 legacy refs 或误把对话照片当成 Archive 来源。

## Proposed Solution

新增一个 iOS 仓库入口的跨仓 source identity gate，组合 iOS 模型/client 检查与后端来源合同测试；将 gate 接入 release regression 和 release QA package guard。修正文档中历史 `archiveImageAnalysis` 的来源解释，新增 Task 19 状态与部署验收说明。验证通过后分别提交推送两个仓库，部署后端，并使用认证 smoke 用户调用线上只读 audit endpoint，确认 Postgres 合同与权限边界。

## Acceptance Criteria

- 一条命令能验证 iOS canonical 生成、typed audit consumer、后端 canonical proposal、只读 audit 与 ownership 路由。
- release regression 默认执行本地 source identity gate，release package guard 防止入口被移除。
- 文档明确区分 `conversationPhoto`、`memoryArchiveItem` 与 legacy `archiveImageAnalysis`，不承诺或执行猜测迁移。
- iOS generic simulator build、generic iPhoneOS build、相关 release regression、后端完整测试和 `git diff --check` 通过。
- iOS 与后端分别提交并推送；后端部署到现有服务器。
- 线上 Postgres smoke 验证 `/kb/source-ref-audit/{userId}` 返回 schemaVersion=1、聚合计数与合法 recommendedAction，且不包含实体内容或 source IDs。

## Verification Plan

1. 运行新增跨仓 gate 与 release QA package check。
2. 运行后端 `verify_backend.sh`。
3. 运行 iOS generic Simulator 和 generic iPhoneOS 无签名构建。
4. 运行 release regression 的非真机必需路径并保存报告。
5. 分仓 `git diff --check`、提交、推送。
6. SSH 服务器拉取 main、重建 API 容器、检查 health/store。
7. 使用独立认证 smoke 用户在线写入一条 canonical knowledge proposal 后调用 audit endpoint，校验只读聚合合同与 ownership。

## Risks

- 线上已有 legacy refs，audit 可能返回迁移建议；这是预期证据，不应触发自动迁移。
- release regression 范围较大，应避免启用真机和无关 provider gate。
- 部署必须保留服务器私密 `.env`，不得在仓库或日志输出凭据。

## Assumptions

- 服务器 SSH 与现有部署目录仍可用，后端分支为 `main`。
- 用户允许本轮提交、推送和部署，但不要求真机验证。
- 历史来源数据迁移需要独立批准，不属于本任务。
