# 实现后端知识操作凭据

## Problem Definition

现有 store 无法确认重复 operation ID 的业务意图是否一致，且 Archive 无级联删除与 governance snapshot-dependent action 无完整幂等语义。

## Proposed Solution

新增稳定 fingerprint 与冲突异常，在 Memory/Postgres 建立独立 receipt；各 API 在业务副作用前检查 receipt，并在相同事务中记录权威结果。新记录严格比较 kind/hash，旧 change 走 unverified legacy 兼容。

## Acceptance Criteria

- 五类 operation kind 均有稳定指纹和结构化冲突。
- Receipt 覆盖有/无 mutation 的 Archive 删除和 governance 原样重放。
- Postgres receipt、snapshot、change、archive 原子提交/回滚。
- API 只返回 operationPayloadVerified 布尔值。
- 相关单元测试和组合 smoke 通过。

## Verification Plan

运行 core services、archive store、Postgres store、API route 相关测试和全量 pytest；运行知识治理 backend smoke 并检查 git diff。

## Risks

- Fake Postgres cursor 需同步新 SQL。
- 并发 insert 冲突必须回读并验证，而不是吞掉数据库唯一冲突。
- Legacy 行不能推断为可信 exact payload。

## Assumptions

- 本轮只做 additive schema 初始化，不执行线上部署。
- baseRevision 不进入稳定指纹。
