# iOS payload conflict 恢复实现结果

## Summary

Backend client 现保留结构化 error code、operation ID 和展示 detail；KnowledgeSyncCoordinator 对普通 mutation 和 governance payload conflict 分别执行可恢复状态机；治理 outbox 支持向后兼容的 recovery/quarantine 元数据、语义幂等 enqueue 和原子 replace。

## Evidence

- 普通 pending 在 payload conflict 后先删除 poisoned operation，再拉取权威 change feed 并用新 ID 重建 delta。
- Governance 首次冲突旋转 operation ID 并迁移 completion，第二次持久化 quarantine；dispatcher 跳过隔离项并继续后续队列。
- 同 ID/同 action enqueue 为 no-op，同 ID/不同 action 在发网前拒绝；operation ID 统一 trim。
- 旧 outbox JSON 缺少 recovery/quarantine 字段时默认解码为 0/nil。
- governance model/client/coordinator、knowledge pipeline 与跨仓 gate 通过；224 项后端组合测试通过；iOS Simulator workspace build 成功。

## Remaining Risk

- Coordinator 仍由纯策略 smoke 和源码门禁验证，工程当前没有独立 XCTest target 注入网络失败；最终 release regression 将再次覆盖。
- 不做公开 UI 和真机验证。
