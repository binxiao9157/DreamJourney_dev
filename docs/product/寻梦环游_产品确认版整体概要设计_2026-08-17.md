## 3. 产品确认后的关键结论

### 3.1 保持不变

- 三页主导航、密码/手机号验证码双登录和账户会话。
- 自己/家人档案双模式。
- 文字 Source → Candidate → 待确认 → MemoryVersion 的 V4 主链路。
- 自然访谈、Live 会后整理与待确认。
- 家人邀请、星辰状态、心境追踪和家庭贡献。
- 音色复刻及单个声音主体累计最多 5 次创建限制。
- 注销、恢复、最终清理和权限隔离。
- KBLite 作为用户不可见的后台兼容逻辑，现有读写和权限行为保持不变。

### 3.2 必须改变

1. 测试账号管理增加超级权限、Owner、Family、平台运维角色及显式功能权限。
2. experience、knowledge、emotion 保持一级类型，同时增加人物、时间、地点、关系、情绪、价值观、人格、可信度和来源 facets。
3. Owner 回响按问题检索相关正式记忆，不再按 Projection 固定顺序装载。
4. 切换到家人不代表可以读取家人的私人 V4；只有家人本人登录自己的账号才能进入自己的 Owner V4。
5. Family/Visitor 查询他人内容必须通过 PublicationVersion、PublicProjection 和 ShareGrant。
6. 回响页面不展示 Citation，但服务端继续保存类型化引用和审计信息。
7. 增加“全部正式记忆”入口、全文查看和 Owner 二次确认编辑。
8. 数据导出改为当前正式记忆的 Markdown 文档。
9. 补齐发布草稿、二次确认、授权、Visitor 查询的 App 完整闭环，并移除 M2/QA 产品限制。
10. 首版图片和 TXT/PDF/DOCX/Markdown 文档理解进入 V4 候选链路；音频和视频暂时关闭。
11. 数字人暂时关闭。
12. 时光信和延迟回复暂时关闭。
13. 增加统一消息中心、“我的”入口及记忆档案/回响右上角未读铃铛。

## 4. 产品确认点的口径收敛

### 4.1 测试白名单与产品权限

产品确认要求白名单支持超级权限、Owner、Family 和平台运维角色。该要求与“登录白名单不得自动获得产品权限”按以下方式兼容：

- 测试账号创建时必须由管理员显式选择 testRole 和 featureEntitlements。
- 仅进入白名单但未分配权限的账号，只获得测试验证码能力。
- superTest 可获得全部已启用产品 Feature，但不能绕过 Vault、ShareGrant、数据归属和审计。
- ownerTest 可测试 Owner 产品能力，只能管理自己的 Vault。
- familyTest 用于构造家庭成员场景，真实数据权限仍来自 Relationship 和 Grant。
- operatorTest 进入运营后台，不自动获得任何用户私人 Vault 读取权。

### 4.2 家人管理是通用功能

- 生产环境：所有正常认证 Owner 均可使用家人管理。
- 测试环境：superTest、ownerTest 可见家人管理；familyTest 只显示与其关系和受邀任务相关的入口。
- 白名单只控制测试场景，不成为生产用户资格系统。

### 4.3 Family、Visitor 与 Owner V4

- 每个真实账户都是自己 Vault 的 Owner。
- A 在自己的 App 中切换到家人 B，只是切换展示身份，不获得 B 的私人 V4 Authority。
- B 必须登录 B 自己的账号，才能以 Owner 身份访问 B 的 Source、Candidate、MemoryVersion 和 Projection。
- A 若查询 B 授权分享的内容，必须作为 Visitor 使用 B 的 ShareGrant 和 PublicProjection。
- A 若帮助 B 补充素材，必须走 FamilyContribution Grant，不得直接写入 B 的正式记忆。

### 4.4 “全部开放”与暂时关闭

- Publication、Visitor、家人、Owner V4、正式记忆等移除 M1-M4 和 QA/封闭试点产品门槛。
- Release Policy 仍保留，用于紧急关闭、最低版本、故障降级和供应商健康检查。
- DH-001 按产品确认保持关闭。
- NOTI-001 中的时光信和延迟回复保持关闭；APNs 可继续用于任务完成等普通通知。

### 4.5 正式记忆导出与法定数据导出

产品页面中的“导出”调整为正式记忆 Markdown。

1. 用户产品入口只导出当前正式记忆 Markdown。
2. 客户端不提供完整账户数据导出入口。
3. 脱敏完整数据只能由用户联系平台、签署协议并经过运维权限、审批和审计后导出；全链路留痕。
4. 运维完整数据导出本阶段延期实现，不能因后端已有 ZIP Job 而标记为产品可用。

### 4.6 账户、版本和音色补充口径

- 账户同时支持密码登录和手机号验证码登录；密码设置、修改、重置、锁定和 OTP 再认证必须形成完整合同。
- 正式记忆保留 current + 3 个历史快照；用户不能手动删除历史快照，系统在新增第 4 个历史快照时滚动替换最旧快照。
- 单个声音主体累计最多创建 5 次音色；该限制不是 TTS 合成次数，家庭关系仍不能代替声音主体授权。
- Publication/Visitor 不设置产品查询次数和 Owner 次数设置，但服务端防刷、成本保护和 Provider 配额限流继续生效。

### 4.7 消息中心与 KBLite 用户边界

- “我的”增加消息中心入口；记忆档案和回响右上角常驻铃铛，未读消息显示数字红标。
- 消息中心支持单条已读、一键已读和一键删除已读通知。
- KBLite 不提供任何用户页面或入口；现有后端读写和权限行为保持不变，且不得绕过账户、Vault、Grant 或跨账号隔离。

## 6. 身份、角色与授权设计

### 6.1 角色模型

| 角色 | 权限来源 | 可访问内容 |
|---|---|---|
| Owner | 认证主体与 Vault ownerSubjectId 一致 | 自己的私人 Source、Candidate、MemoryVersion、Projection |
| Family | FamilyRelationship + 专项 Grant | 被授权的贡献任务；不能读私人 V4 |
| Visitor | ShareGrant + VisitorSession | PublicProjection |
| Operator | 独立后台 Principal 和 Scope | 运营元数据；默认不能读私人内容 |
| Admin | 独立后台强认证 | 配置与审计；私人内容访问需另行审批和留痕 |
| superTest | 测试账号显式 entitlement | 全产品功能入口，但仍受数据归属约束 |

### 6.2 测试账号数据结构

现有 test account record 增加：

| 字段 | 类型 | 说明 |
|---|---|---|
| testRole | enum | superTest、ownerTest、familyTest、operatorTest |
| featureEntitlements | string[] | 显式允许测试的 Feature 集合 |
| scenarioBindings | JSON | 可选的家庭关系、Grant、测试数据场景引用 |
| entitlementRevision | int | 权限修订号 |
| updatedByHash | string | 管理员审计标识 |

令牌中只携带最小的 entitlement snapshot 标识，服务端每次请求仍查询或验证当前修订。角色修改后旧会话必须撤销。

### 6.3 测试超级权限边界

superTest 不能：

- 指定任意 vaultId 读取别人数据。
- 跳过 Owner/Family/Visitor 权限判断。
- 伪造 ShareGrant。
- 使用未授权声音、肖像或数字人资产。
- 绕过注销、删除和审计。

## 7. V4 记忆模型 V2

### 7.1 主链路

~~~mermaid
flowchart LR
    INPUT["文字/图片/文档/访谈/Live\n音频/视频首版关闭"] --> SOURCE["Source"]
    SOURCE --> EXTRACT["ExtractionResult"]
    EXTRACT --> CAND["Candidate\nkind + facets"]
    CAND --> REVIEW{"Owner 确认"}
    REVIEW -->|接受/更正| MV["MemoryVersion V2"]
    REVIEW -->|拒绝| HISTORY["Decision History"]
    MV --> PROJ["MemoryProjection"]
    PROJ --> SEARCH["SearchDocument"]
    SEARCH --> CONTEXT["Query-relevant Context"]
~~~

### 7.2 一级记忆类型

| kind | 核心内容 |
|---|---|
| experience | 经历、事件、人生片段，核心字段 summary |
| knowledge | 知识、判断、经验方法和观点，核心字段 claim |
| emotion | 情感体验、偏好和依恋，核心字段 label/description |

同一 Source 可以生成多个不同 kind 的 Candidate；一条 Candidate 只有一个主 kind，但可以同时携带多个 facets。

### 7.3 facets 结构

新增 contentSchemaVersion：owner-truth-v2。建议结构：

~~~json
{
  "content": {
    "summary": "小时候父亲经常带我去河边钓鱼"
  },
  "facets": {
    "people": [
      {"name": "父亲", "role": "family", "relationship": "father"}
    ],
    "time": [
      {"lifeStage": "childhood", "precision": "approximate"}
    ],
    "places": [
      {"name": "河边"}
    ],
    "relationships": [
      {"subject": "我", "object": "父亲", "type": "parentChild"}
    ],
    "emotions": [
      {"label": "放松", "target": "与父亲钓鱼", "intensity": "medium"}
    ],
    "values": [
      {"label": "耐心", "statement": "做事要有耐心"}
    ],
    "personality": [
      {"trait": "耐心", "evidenceMode": "ownerReported"}
    ],
    "confidence": {
      "level": "high"
    }
  }
}
~~~

Source references、perspective、epistemic、sensitivity 和 contentHash 继续作为外层权威元数据，不重复塞入 facets。

### 7.4 facets 校验规则

1. facets 全部可为空，但结构必须符合 schema。
2. AI 推断的人格或价值观必须标记 evidenceMode=inferred，并保持 epistemic=inferred/uncertain。
3. Owner 更正 facets 时与正文一起生成新的 MemoryVersion。
4. 关系 facet 不能替代 FamilyRelationship 权限实体。
5. confidence 表示内容可信程度，不赋予访问权限。
6. 未识别的 schemaVersion 继续 quarantine，不能进入 Projection。

### 7.5 存储方式

为保持架构轻量：

- MemoryVersion 的内容和 facets 继续使用版本化 JSONB。
- 不为每种 facet 新建独立业务表。
- Projection Worker 将可检索字段扁平化到 SearchDocument.structured_terms。
- PostgreSQL 为 facets JSONB 和常用 structured_terms 建立 GIN 索引。
- 人物关系图等 UI 从 Projection 派生，KBLite 不再新增权威写入。

### 7.6 V1 兼容

- 已有 owner-truth-v1 记忆继续可读。
- 新 Candidate 默认写 owner-truth-v2。
- V1 投影时生成空 facets，不自动推断并回写。
- 只有用户重新确认或更正后才生成 V2 MemoryVersion。

## 8. 正式记忆总览与编辑

### 8.1 页面设计

在“记忆档案”增加“正式记忆”入口，仅在自己 Owner 身份展示。

正式记忆页包含：

- 当前正式记忆列表。
- experience、knowledge、emotion 筛选。
- 人物、时间、地点、关系、价值观等 facets 筛选。
- 关键词搜索。
- 全文详情。
- 版本历史。
- Owner 编辑。
- 选择并创建共享副本。

“我记录的记忆”继续表示 Source/素材；“我的自传”继续表示阅读视图；不得再用这两个页面替代正式记忆总览。

### 8.2 聚合读取接口

新增：

GET /v2/vaults/{vaultId}/memories

主要参数：

- status=current，固定只读当前版本。
- kind。
- query。
- facet filters。
- cursor、limit。

响应返回：

- memoryId、memoryVersionId、versionNumber。
- kind、content、facets。
- perspective、epistemic、sensitivity。
- createdAt、updatedAt。
- sourceCount 和可审计引用摘要。

Owner-only，no-store，不返回原始 Source 内容。

### 8.3 二次确认编辑

编辑流程：

1. Owner 打开正式记忆详情。
2. App 在内存中创建编辑草稿，不立即写后端。
3. Owner 修改正文或 facets。
4. 点击保存后展示差异预览和二次确认。
5. 确认后提交 correction command。
6. 服务端原子创建新 MemoryVersion、correction link 和 DecisionReceipt。
7. Projection/SearchDocument 异步更新。

版本保留规则：

- 详情展示当前版本和最多 3 个历史快照。
- 用户不能手动删除历史快照。
- 新版本导致历史快照超过 3 个时，由系统滚动淘汰最旧历史快照。
- PublicationVersion 的不可变快照独立保留；账户注销、法定删除和备份保留遵循各自规则。

如果 App 在二次确认前关闭、返回或崩溃：

- 本地草稿不落盘。
- 不调用服务端写接口。
- 本次修改视为取消。

新增命令：

POST /v2/vaults/{vaultId}/memories/{memoryId}/corrections

命令至少包含 commandId、expectedVersion、expectedContentHash、contentSchemaVersion、correctedContent 和 secondConfirmation=true。

并发冲突返回 409，客户端重新加载后再编辑。

## 9. 检索与回响设计

### 9.1 Owner 私人回响

Owner 自己身份的问答链路：

问题预处理 → SearchDocument 检索 → Top-K MemoryVersion → Authority/版本/哈希复核 → Context Packet → DeepSeek → 回答。

当前 projectionCitationOrder 改为 queryTextDeterministicFallback 作为生产默认。百级用户阶段不强制引入向量数据库。

建议约束：

- 检索候选最多 20 条。
- 最终 Context 最多 8 条。
- generationContext 最多 4,096 字。
- 无命中返回 memory gap，不为了提高命中新增或扩大 KBLite/Legacy Archive 回退；KBLite 现有已授权后台行为保持不变。

### 9.2 Family/Visitor 查询

~~~mermaid
flowchart TD
    Q["用户在自己的账号提问"] --> SELF{"查询自己的 Vault?"}
    SELF -->|是| OWNER["Owner V4 Projection"]
    SELF -->|否| GRANT{"存在有效 ShareGrant?"}
    GRANT -->|是| PUBLIC["PublicProjection Visitor 查询"]
    GRANT -->|否| DENY["无权访问/引导贡献"]
~~~

切换到家人身份后：

- 不创建对方 OwnerTruthCommandContext。
- 不读取对方 Source、Candidate、MemoryVersion、私人 Projection。
- 有 ShareGrant 时切换到 VisitorSession/PublicProjection。
- 无 ShareGrant 时只显示公开资料和记忆缺口引导。
- 严禁回退旧 Archive/KBLite 读取家人私人事实。

### 9.3 Citation 产品展示

- 后端继续生成 typed citations、contextTraceId 和 contentHash。
- iOS 回响页面不显示来源卡片、引用编号或原文入口。
- Citation 仅用于审计、纠错、内部 QA 和回答反馈。
- 无记忆命中时 citations 为空，memoryGrounding=gap。
- 修复 grounded 识别，将 ownerTruthMemoryProjection 计入 grounded 来源。

### 9.4 Live

Live 保持当前产品确认：

- 用户打开后保持单次会话。
- 支持自然轮次与打断。
- 用户关闭或 60 秒无输入结束。
- 会后只以 Owner turn 为事实证据。
- DeepSeek 整理后进入待确认记忆。
- 文字答案和 Live 使用同一火山语音链路。

## 10. 多媒体进入 V4

### 10.1 统一处理管线

上传意图 → 私有对象存储 → 完整性校验 → ClamAV/安全扫描 → 类型处理 → ExtractionResult → Candidate → Owner 确认。

### 10.2 首版类型处理

| 类型 | 处理 |
|---|---|
| 图片 | OCR、图片描述、时间地点和人物候选 |
| TXT | 字符集识别、正文解析 |
| PDF | 文本层解析；无文本时受控 OCR |
| DOCX | 段落、标题、图片说明解析 |
| Markdown | UTF-8 文本、标题层级、段落和来源片段解析 |

音频和视频首版暂时关闭，普通用户看不到入口，后端普通流量不创建对应处理任务。只有解析成功、Source 引用完整的图片和文档内容才进入 Candidate。

### 10.3 隐私与失败

- 外部 OCR/ASR/视觉处理前取得明确同意。
- 供应商只接收完成当前任务所需的数据。
- 原始媒体不写入模型日志。
- 处理失败保持 Source 和对象，不生成伪 Candidate。
- 支持独立重试和删除回执。

## 11. 正式记忆 Markdown 导出

### 11.1 用户入口

“我的 → 正式记忆导出”创建异步任务，完成后下载单个 UTF-8 Markdown 文件。

文件名建议：

寻梦环游-正式记忆-YYYYMMDD-HHmm.md

Content-Type：

text/markdown; charset=utf-8

### 11.2 导出范围

只导出：

- 当前 status=current 的 MemoryVersion。
- 正文内容。
- 一级 kind。
- 已确认 facets。
- 创建/更新时间。
- 版本号。

不导出：

- Source 原文。
- 待确认或已拒绝 Candidate。
- 历史 superseded MemoryVersion 正文。
- 账户凭据。
- 媒体二进制。
- 供应商资产和内部审计记录。

### 11.3 Markdown 结构

~~~markdown
# 我的正式记忆

导出时间：2026-08-17 18:00

## 经历

### 小时候与父亲钓鱼

小时候父亲经常带我去河边钓鱼。

- 人物：父亲
- 地点：河边
- 人生阶段：童年
- 情绪：放松
- 价值观：耐心
- 记忆版本：3
~~~

### 11.4 当前实现修改

当前后端导出为 ZIP，包含 data-export.json、permissions.json 和可选媒体。需要：

- 新增 exportType=formalMemoryMarkdown。
- 新增 Markdown renderer。
- 下载响应改为 text/markdown 和 .md。
- iOS 更新文件类型、分享预览和页面范围说明。
- 客户端不展示 fullAccountArchive；脱敏完整数据导出仅预留运维审批/审计合同，本阶段不实现产品能力。
