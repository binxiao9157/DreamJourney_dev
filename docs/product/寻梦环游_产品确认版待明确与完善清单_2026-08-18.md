## 4. P0 产品决策

### PCQ-01 家人管理的生产资格与测试白名单关系

现有不一致：

- PRD 验收标准写“家人管理是通用功能，不由测试白名单决定”。
- 产品批注又写“由测试白名单中的超级权限者、Owner 权限者决定”。
- 概要设计将其解释为生产 Owner 通用、测试环境由 testRole/entitlement 控制。

建议口径：

1. 生产环境中所有正常认证 Owner 均可进入家人管理。
2. 测试白名单只决定测试 OTP 资格。
3. 测试账号的 `superTest/ownerTest/familyTest/operatorTest` 和 feature entitlements 只影响测试场景。
4. 无论测试角色如何，都不能绕过 Vault、FamilyRelationship、ShareGrant 和审计。

阻断范围：GAP-01 的数据库字段、Token revision、管理页和 Session 撤销实现。

产品最终确认：`CONFIRMED`。生产正常认证 Owner 均可进入家人管理；测试白名单只控制测试 OTP，显式测试角色/entitlement 不得绕过 Vault、Grant 和审计。

### PCQ-02 手机号 OTP 与修改密码的账户模型

现有不一致：

- AUTH-001 定义手机号验证码登录和注册。
- PROF-001 要求验证当前密码后修改密码。
- 两份输入没有说明密码是否也是登录凭据。

确认口径：

1. 同时支持密码登录和手机号验证码登录。
2. 密码模式必须补齐设置密码、密码登录、修改、忘记/重置、锁定和风控。
3. OTP 同时用于独立登录和敏感操作再认证；两种方式使用同一账户与 Session 模型。

阻断范围：认证数据模型、Profile 入口和后端密码接口。

产品最终确认：`CONFIRMED`。同时支持密码登录和手机号验证码登录；补齐设置/修改/重置密码、验证码再认证、锁定与风控合同，不保留只有“修改密码”而没有完整登录模型的孤立入口。

### PCQ-03 家人音色的独立授权流程

当前明确边界：家庭关系本身不构成声音授权，但尚无完整授权产品流程。

确认口径：

1. 音色主体必须在自己的账户中完成身份、录音、授权和质量接受。
2. 授权按用途区分：本人私用、指定 Family 私用、Publication/Visitor 使用。
3. 授权记录绑定 voiceProfileId、主体、被授权账户、用途、有效期和版本。
4. 主体可撤销；撤销后立即停止新合成，并进入缓存和 Provider 资产清理流程。
5. 家庭关系、代录、素材上传和 superTest 都不能代替声音主体授权。
6. 逝者、未成年人和无法自行确认的主体不从该流程自动推导为可用。

阻断范围：家人音色绑定、Echo 角色选音和未来 Visitor 语音。

产品最终确认：`CONFIRMED`。采用上述独立授权流程；单个声音主体累计最多创建 5 次音色，此限制是音色创建次数，不是 TTS 合成调用次数。服务端成功受理并创建新 profile 时计数；参数校验失败和同一 commandId 幂等重放不计数，后续训练失败、删除或撤销不返还次数。

### PCQ-04 Publication/Visitor Grant 产品规则

当前缺口：已明确使用 PublicationVersion、PublicProjection 和 ShareGrant，但未定义完整获客和使用规则。

建议口径：

1. 首版只向已注册账户通过手机号或账户 ID 发出邀请，不开放匿名公开链接。
2. Grant 必须有明确接收人、范围、版本、有效期和撤销状态。
3. 产品查询次数不限，不提供 Owner 次数设置；服务端保留防刷、成本保护、异常流量和 Provider 配额限流。
4. Visitor 首版支持文字和普通语音，不自动使用复刻音色，数字人按产品确认关闭。
5. Publication 创建时提示第三方人物和敏感内容；默认不自动公开原始 Source 或未确认推断。
6. 撤销、过期或发布暂停后，现有 VisitorSession 立即失效。

阻断范围：GAP-09/GAP-10 的 Grant API、邀请 UI、VisitorSession 和语音策略。

产品最终确认：`CONFIRMED`。当前产品层面不限制 Visitor 查询次数，也不提供 Owner 次数设置；服务端继续保留防刷、成本保护、异常流量和 Provider 配额所需的安全限流。

### PCQ-05 家庭关系解除与数据处置

当前缺口：文档明确暂不提供“删除家人”，但没有关系退出、解除和历史数据处置规则。

建议口径：

1. 首版提供“退出家庭/解除关系”而不是删除对方账户。
2. 解除前二次确认，并分别列出 ShareGrant、Contribution Grant、待审核贡献和角色切换影响。
3. 解除后立即撤销新访问和新贡献；未接受贡献对双方隐藏并进入处置队列。
4. 已被 Owner 接受形成 Source 的贡献继续保留来源审计，不因关系解除改写正式记忆。
5. Publication Grant 是否继续有效必须由 Owner 单独选择，不能由关系解除隐式决定。

阻断范围：Family API、关系状态机、消息通知和撤权回归。

产品最终确认：`CONFIRMED`。首版只提供退出家庭/解除关系，不删除对方账户；账户删除只能由账户本人发起，解除后的 Grant、贡献和已接受 Source 按上述建议处置。

### PCQ-06 关闭能力的历史数据与重新开放条件

当前明确：数字人、时光信和延迟回复暂时关闭；产品未正式发布，不存在生产历史时光信或延迟回复数据。

仍需确认：

1. 历史时光信和延迟回复是否在普通 App 中提供只读入口。
2. 未到期时光信关闭期间是否永久跳过，还是重新开放后重新计算投递。
3. 已创建数字人 Session、缓存和资产引用是立即清理还是仅停止调用。
4. 用户是否看到统一“功能维护中”说明，还是完全隐藏。
5. 重新开放需要哪些产品确认和迁移步骤。

建议口径：

- 普通用户入口完全隐藏；客服/数据权利流程可查询历史元数据。
- 不补发关闭期间到期的信件和延迟回复，除非用户重新确认。
- 数字人 Session 立即释放，Provider 资产按原授权和保留规则处理。
- 重新开放必须进行独立产品确认、数据迁移和功能验收。

阻断范围：GAP-11/GAP-12 的历史数据迁移和关闭回归。

产品最终确认：`CONFIRMED / NOT_APPLICABLE_PRODUCTION_HISTORY`。产品尚未正式发布，不存在生产历史时光信或延迟回复，因此不实施历史用户数据迁移；功能仍按确认范围关闭，开发/测试数据不作为生产历史补发。

## 5. P1 规格完善

### PCQ-07 正式记忆编辑、删除和发布版本关系

建议口径：

1. Owner 可编辑正文和已确认 facets，每次编辑创建新 MemoryVersion。
2. 正式记忆不直接物理删除；首版提供停用/移出回响，数据删除走数据权利流程。
3. PublicationVersion 永久绑定发布时的旧 MemoryVersion 快照。
4. 私人记忆更新后，已发布副本不自动变化；Owner 必须创建新 Draft 并再次确认。
5. 并发编辑使用 expectedVersion/contentHash，冲突后重新加载。

产品最终确认：`CONFIRMED`。保留“当前版本 + 最多 3 个历史快照”；用户不能手动删除历史快照，产生第 4 个历史快照时由系统按最旧优先滚动覆盖。PublicationVersion 的不可变快照及法定数据删除不受该展示保留规则替代。

### PCQ-08 Facets 字典和 AI 推断展示

建议口径：

1. 人物、地点允许自由文本；关系、情绪、人生阶段、可信度优先使用受控枚举并允许“其他”。
2. 价值观和人格默认标记证据来源，不显示成诊断或确定结论。
3. `evidenceMode=inferred` 的人格/价值观在待确认页弱化展示，必须由 Owner 确认后才进入正式记忆。
4. Facet 字典使用版本号，新增枚举不要求批量改写旧 MemoryVersion。

产品最终确认：`CONFIRMED`。采用上述 facets 字典、推断标识和 Owner 确认规则。

### PCQ-09 多媒体格式、限制和首版处理范围

确认口径：

| 类型 | 首版格式 | 限制 | 首版处理 |

产品最终确认：`CONFIRMED`。首版只开放图片和文档；文档支持 TXT、PDF、DOCX、Markdown（`.md`）。音频和视频入口及处理能力暂时不开放，不以 mock 状态冒充可用。

### PCQ-10 相关检索的产品验收标准

建议口径：

1. 建立固定的本人事实、无关问题、纠正后问题、删除后问题和跨账号问题集。
2. 相关正式记忆命中率、错误引用率和无命中准确率分别验收。
3. Top-K 和 Context 长度是工程上限，不作为质量结论。
4. 无相关记忆时必须返回 gap；不得为了提高命中率读取 Legacy/KBLite 或未确认 Candidate。
5. 排名算法可迭代，但每次变更保留版本和离线对比结果。

产品最终确认：`CONFIRMED`。采用上述检索验收、无命中 gap 和版本化离线对比规则。

### PCQ-11 正式记忆导出与完整账户导出入口

3. 脱敏完整数据只能由用户联系平台、签署协议并经过运维权限、审批和审计后导出。

产品最终确认：`CONFIRMED`。KBLite 对用户完全不可见，不提供页面或入口；现有后端读写行为和权限保持不变，不因隐藏而新增、收紧或扩大访问权，任何现有调用仍必须遵守账户/Vault/Grant 隔离。

### PCQ-13 普通任务通知范围

建议保留通知事件：

1. Candidate 整理完成并可审核。
2. 正式记忆投影或导出任务完成/失败。
3. 家庭邀请、贡献审核结果和授权撤销。
