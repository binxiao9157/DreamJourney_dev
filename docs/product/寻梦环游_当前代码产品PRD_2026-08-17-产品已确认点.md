## 4. 产品定位

寻梦环游是一款面向个人与家庭的记忆沉淀和回响陪伴产品。用户可以记录文字、图片等记忆素材，经整理与本人确认后形成可追溯的正式记忆；在回响中，AI 助手或被授权的家人数字身份基于可访问的记忆进行自然对话。

产品遵循以下原则：

1. 原始素材不直接等于正式记忆。
2. AI 整理结果必须进入待确认流程，用户确认后才成为事实权威。
3. 回响回答应基于当前身份有权访问的正式记忆，并提供来源引用。
4. 没有相关记忆时，应自然转入访谈或家庭贡献，而不是伪造答案。
5. 家人关系、记忆访问权、声音权和数字人使用权相互独立。
6. 高风险能力必须服务端放行，并在供应商不可用时安全降级。

## 5. 用户与角色

| 角色 | 产品含义 | 当前主要能力 |
|---|---|---|
| Owner | 账户与私人记忆库的所有者 | 记录、确认、纠正、删除、问答、授权家庭贡献、数据导出和注销 |
| Family | 与 Owner 建立家庭关系的成员 | 被邀请、切换身份、在获得单独授权后贡献素材 |
| Visitor | 通过有效 ShareGrant 访问已发布副本的人 | 仅访问发布域中的公开投影；当前为 M2 QA/封闭试点 |
| Operator/Admin | 平台运营与管理员 | 测试账号、运行状态和内部治理；不属于普通 App 用户 |
| AI 助手 | Owner 切换到“自己”时的回响身份 | 通过访谈帮助 Owner 沉淀自己的记忆，明确披露非真人 |
| 家人数字身份 | Owner 切换到家人后的回响身份 | 展示家人档案与回响；V4 权威上下文和家人声音仍有实现边界 |

## 6. 信息架构

登录成功后进入三个一级页面：

1. 记忆档案：自传入口、记忆素材、待确认记忆和访谈整理。
2. 回响：文字问答、Live 实时语音、语音播放和数字人运行界面。
3. 我的：个人资料、家人管理、心境追踪、音色复刻、发布访问、法律、数据权利和账户管理。

默认进入“回响”页。切换当前家人身份后，记忆档案和回响使用同一当前身份上下文。

## 8. 详细产品需求

### 8.1 应用与认证

#### APP-001 三页主导航与账户态进入

用户故事：作为已登录用户，我希望进入稳定的记忆档案、回响和我的三个一级页面，并在当前身份改变后看到一致的数据。

验收标准：

1. 未验证账户不能进入主页面。
2. 登录后默认选中回响。
3. 三个一级页面之间切换不丢失当前 Owner/家人上下文。
4. 账户权限撤销、退出或注销后立即离开主页面。

**产品确认点**：确认通过。

#### AUTH-001 手机号验证码登录与注册

用户故事：作为新用户或老用户，我可以通过手机号和验证码创建账户或登录。

验收标准：

1. 手机号必须为 11 位，验证码不能为空。
2. 支持获取、重新发送验证码。
3. 登录与注册模式可切换；注册必须先完成手机号验证。
4. 错误、过期或已使用验证码返回可理解的错误。
5. 认证成功后建立后端会话和本地 AccountLease。

**产品确认点**：确认通过。

#### AUTH-002 会话续期、退出与前后台恢复

验收标准：

1. Access Token 到期前后可使用 Refresh Token 续期。
2. 前台恢复时重新验证账户与功能策略。
3. 退出登录清理本地敏感账户态。
4. 账户被撤销时，现有请求和页面不得继续访问私人数据。

**产品确认点**：确认通过。

#### AUTH-003 测试账号白名单管理

内部需求：

1. 管理员可登录独立后台管理页。
2. 可创建测试手机号、轮换验证码、启用或停用账号。
3. 测试账号只绕过指定环境的 OTP，不获得额外产品权限。
4. 白名单不得决定家人管理、V4 记忆、音色或数字人等产品资格。

**产品确认点**：白名单里应有多种权限的切换，包含超级权限（拥有所有产品权限）、Owner、Family以及平台运维角色。

### 8.2 记忆档案

#### ARCH-001 自己/家人档案双模式

验收标准：

1. 切换到自己时标题为“我的自传”，允许新增和编辑自己的素材。
2. 切换到家人时标题为“{姓名}的故事”，默认只读。
3. 当前身份切换后，书本、素材列表和回响身份同步更新。
4. 家人关系本身不能自动授予私人 Vault 的写权限。

**产品确认点**：确认通过。

#### ARCH-002 记忆素材列表、详情和管理

验收标准：

1. 展示文字、图片、音频、视频和时光信等已有素材类型。
2. 自己模式可查看详情并按权限编辑或删除；家人模式只读。
3. 同步失败时明确展示状态，不能把本地未同步内容伪装为云端已保存。
4. 每条素材保留创建时间、类型、处理状态、摘要和标签等元数据。

**产品确认点**：确认通过。

#### ARCH-003 Owner 文字素材进入 V4

验收标准：

1. Owner 可提交不超过 20,000 字的文字。
2. 新文字先形成 Source，不直接成为正式记忆。
3. Source 进入候选整理与待确认流程。
4. V4 权威打开后，旧 Archive 文本写入应被服务端拒绝，避免双权威。

**产品确认点**：确认通过。

#### ARCH-004 多媒体素材

验收标准：

1. 支持选择图片、音频、文档和视频；具体入口按服务端能力展示。
2. 图片上限 20 MB；音频、文档和视频上限 50 MB。
3. 涉及外部处理的图片或音频必须由用户明确同意。
4. 文件进入私有对象存储，扫描通过后才可进入 OCR/ASR/解析。
5. 当前文档和视频主要完成安全保存，内容理解能力不得误标为已完成。

**产品确认点**：确认通过。

#### ARCH-005 自传与故事书本阅读

验收标准：

1. 档案顶部展示可点击的书本入口。
2. 自己模式进入“我的自传”，家人模式进入“TA 的故事”。
3. 正文按成长与求学、家庭与生活、工作与感悟等章节组织。
4. 展示真实页码和来源素材，不出现虚假的章节统计。
5. 家人模式保持只读。

**产品确认点**：确认通过。

### 8.3 V4 记忆形成

#### MEM-001 三维候选记忆

验收标准：

1. Source 或访谈内容可整理为 experience、knowledge、emotion 三类候选。
2. 候选包含第一人称/转述/推断视角、事实状态和敏感级别。
3. AI 推断不得直接冒充 Owner 明确确认的事实。
4. 候选必须保留 Source 引用和内容哈希。

**产品确认点**：**保留 experience、knowledge、emotion 作为一级记忆类型，但增加关系、人格、价值观等结构化维度作为 facets。** 一条记忆可以同时包含人物、时间、地点、关系、情绪、价值观、可信度和来源，而不能被强制只归入一个孤立类别。。

#### MEM-002 单一待确认入口

验收标准：

1. 记忆档案对用户只展示一个“待确认记忆”入口。
2. 用户可接受、纠正、拒绝候选，也可批量接受。
3. 接受或纠正后进入正式记忆；拒绝后保留审计历史但不参与回响。
4. 候选来源失效、账户切换或权限变化时失败关闭。

**产品确认点**：确认通过。

#### MEM-003 正式记忆版本与追溯

验收标准：

1. 每次接受或纠正产生不可混淆的 MemoryVersion。
2. 当前版本与历史版本可追溯。
3. 纠正建立明确的 correction link。
4. 正式记忆与 Source、DecisionReceipt、MemoryRelation 保持可审计关系。

当前实现边界：

1. 当前没有面向用户的“全部正式记忆”独立总览页。
2. 已确认记忆只能从“待确认记忆”右上角进入“审核记录”，再筛选“已形成正式记忆”的条目。
3. 点击有 memoryId 的审核记录后，可查看该条“正式记忆版本”历史。
4. “我记录的记忆”是素材列表，“我的自传”是素材派生阅读页，二者都不等于 V4 正式记忆总览。
5. 产品后续需要增加仅展示 current MemoryVersion 的正式记忆总览，作为浏览、纠正和发布选择的统一入口。

**产品确认点**：确认通过。

#### MEM-004 投影、索引与相关检索

产品目标：

1. 只有当前、已确认且有权访问的 MemoryVersion 进入 Projection。
2. Projection 派生 SearchDocument，按问题相关性选择有限数量的记忆。
3. 检索结果必须重新校验权限、版本和内容哈希。
4. 回答上下文应限制长度并返回类型化引用。

当前实现边界：

1. 已实现确定性文本索引与查询排序，不是向量语义检索。
2. 当前生产 Owner Echo 桥接仍强制使用 Projection 引用顺序，未启用按问题排序的 SearchDocument 路径。
3. 家人身份的 Echo 还未进入同一 V4 权威链路。

**产品确认点**：家人身份的echo，只能由家人自己的账号进入V4权威链路，family和vistor身份无法进入。

### 8.4 引导访谈

#### INTV-001 自然输入式访谈

验收标准：

1. 用户可一次输入较长叙述，而不是被迫逐题填写表单。
2. 系统根据人物、地点、事件、情绪和细节缺口提出后续问题。
3. 页面明确说明内容不会直接写入正式记忆。
4. 记忆缺口可从回响自然转入该流程。

**产品确认点**：确认通过。

#### INTV-002 话题与节奏控制

验收标准：

1. 用户可切换话题。
2. 支持“跳过一次”“以后再聊”“不要再问”。
3. 用户可恢复之前关闭的话题。
4. 服务端记录边界状态，跨会话保持一致。

**产品确认点**：确认通过。

#### INTV-003 会后整理与待确认

验收标准：

1. 用户主动结束，或 Live 连续 60 秒无输入时结束会话。
2. 完整文字转写可在明确授权和服务端开关打开时发送给 DeepSeek 整理。
3. 只有 Owner 的表达可作为记忆证据；AI 回复用于上下文，不作为 Owner 事实。
4. 整理结果进入待确认记忆，不直接进入正式记忆。
5. 无有效 Owner 内容时不创建空候选。

**产品确认点**：确认通过。

### 8.5 回响

#### ECHO-001 文字回响

验收标准：

1. 用户可输入不超过 2,000 字的问题。
2. 回答只使用当前身份有权访问的记忆上下文。
3. 回答展示文本，并在语音可用时播放。
4. 当前 V4 Owner 自己链路不得回退读取 Legacy Archive、KBLite 或 Care。
5. 家人 V4 权威上下文尚未收口时，产品不得声称已经与 Owner 链路完全一致。

**产品确认点**：确认通过。

#### ECHO-002 Live 实时语音

验收标准：

1. 麦克风由用户主动开启，并在用户关闭前保持同一次 Live 会话。
2. 用户说完一段后，AI 可自然讨论、追问并支持打断。
3. 连续 60 秒无用户输入自动结束。
4. 会话状态包括启动、聆听、思考、等待、播放和异常。
5. 原始音频由实时代理转发，不在代理层持久化。

**产品确认点**：确认通过。

#### ECHO-003 记忆缺口转接

验收标准：

1. 自己身份找不到相关记忆时，回复“我们来聊一聊”并可转入 Owner 访谈。
2. 家人身份找不到相关记忆时，邀请用户贡献故事。
3. 家庭贡献必须先有 Owner 授权。
4. 不得为填补记忆缺口而编造事实。

**产品确认点**：确认通过。

#### ECHO-004 安全、引用与降级

验收标准：

1. 在读取私人记忆和调用模型前执行安全策略。
2. 基于记忆的回答返回来源引用。
3. DeepSeek 不可用时可使用有限的记忆提取式降级，且明确记录降级原因。
4. 无相关记忆时 citations 为空，结果标记为 gap。
5. 回答接口使用 no-store。

当前实现边界：V4 引用来源已生成，但 grounded 判定仍主要识别旧 archive/kbFact/care 来源，需补齐 ownerTruthMemoryProjection 的判定。

**产品确认点**：引用来源无需在回响页面展示。

#### ECHO-005 统一语音播放

验收标准：

1. 文字回响答案使用与 Live 相同的火山实时语音播放链路。
2. 不依赖 iOS 系统 TTS，避免 Android 端出现不同供应商实现。
3. 语音失败不影响文字答案展示。
4. Live 已稳定链路应减少无关改动。

**产品确认点**：确认通过。

### 8.6 家人与关怀

#### FAM-001 家人管理与切换

验收标准：

1. 家人管理是通用功能，不由测试白名单决定。
2. 可切回自己 AI 助手，或切换到已加入的家人。
3. 可通过手机号邀请家人并查看邀请状态。
4. 已建立关系的家人当前不可直接删除；退出/解除关系能力未开放时要明确提示。
5. 身份切换同步影响档案与回响。

**产品确认点**：家人管理是通用功能，由测试白名单中的超级权限者、owner权限者决定。

#### FAM-002 星辰状态与心境追踪

验收标准：

1. 家人列表不直接标注“阳光/星辰”，星辰成员仅以较弱视觉状态提示。
2. 星辰状态必须进入家人详情设置。
3. 开启前二次确认；关闭可直接执行。
4. 仅当家庭中存在星辰成员，且当前为自己 AI 助手或该星辰成员时展示心境追踪。
5. 心境追踪只提供陪伴和风险提示，不构成医疗诊断。

**产品确认点**：确认通过。

#### FAM-003 家庭贡献

验收标准：

1. Owner 可向已接受邀请的 Family 单独授予或撤销贡献权。
2. Family 可提交文字或一张图片。
3. Owner 可接受或拒绝待审核贡献。
4. 被接受内容仍需进入 Owner Truth 整理与确认链路。
5. 撤销后停止新提交并隐藏未接受内容；已接受 Source 保持可审计。

**产品确认点**：确认通过。

### 8.7 我的、数据权利与法律

#### PROF-001 个人资料、密码与法律中心

验收标准：

1. 个人资料支持姓名、性别、地区等字段，手机号只读。
2. 修改密码需验证当前密码，新密码不少于 8 位并二次确认。
3. 法律中心至少展示 AI 辅助说明、心理支持边界、隐私与数据、数字人与伦理和紧急情况。
4. 头像、人格设定等入口按策略显示，未开放时不提供假入口。

**产品确认点**：确认通过。

#### DATA-001 个人数据导出

验收标准：

1. 用户可创建异步导出任务并查看状态。
2. 完成后可下载和系统分享。
3. 临时本地文件分享后删除并使用文件保护。
4. 导出不包含凭据、媒体二进制和供应商持有数据，并在页面说明范围。

**产品确认点**：导出的内容应为正式记忆的内容，导出为markdown文档。

#### DATA-002 注销、恢复与最终清理

验收标准：

1. 注销必须二次确认，提交后立即退出并撤销访问。
2. 提供 30 日可披露恢复窗口和一次恢复机会。
3. 到期后按模块执行物理清理。
4. 供应商删除未取得回执时只能显示“清理中/部分完成”，不能显示“彻底删除”。

**产品确认点**：确认通过。

### 8.8 音色与数字人

#### VOICE-001 音色复刻

验收标准：

1. 用户先完成本人授权，再选择音频样本并提交训练。
2. 展示未提供、训练中、可用、失败、禁用和删除等状态。
3. 支持刷新、重试、质量接受、禁用和删除。
4. 禁用立即阻止合成；删除按供应商回执更新。
5. iOS 不保存供应商密钥。
6. 当前政策只允许满足强成年人身份与活体要求的本人训练；家人声音使用不得被默认视为已开放。

**产品确认点**：确认通过。

#### DH-001 腾讯数字人

验收标准：

1. 后端创建、续约和释放数字人会话。
2. iOS 负责口型/音频驱动与展示。
3. 配额、并发、Key 或供应商异常时安全降级到普通回响。
4. 页面明确“AI 生成，非真人本人”。

**产品确认点**：暂时关闭。

### 8.9 发布与 Visitor

#### PUB-001 Owner 发布副本

验收标准：

1. 发布内容必须来自已确认 MemoryVersion 的独立副本。
2. Owner 二次确认后生成不可变 PublicationVersion。
3. 发布副本与私人 Source/Candidate/MemoryVersion 隔离。
4. Owner 可签发、撤销 ShareGrant，并可暂停发布。
5. 当前能力只按 M2 QA/封闭试点验收，不作为全量功能。

当前实现边界：

1. 后端已有创建 PublicationDraft 和二次确认 PublicationVersion 的受控接口。
2. iOS 当前“发布管理”页只读取已确认发布和授权状态；额外生命周期开关打开时可撤回。
3. iOS 尚未实现从正式记忆中选择内容、填写 publicTitle/publicBody、预览草稿和二次确认发布的页面及客户端调用。
4. 因此普通 Owner 当前无法在 App 内新建或修改共享副本；不可变 PublicationVersion 本身也不应原地修改，变更应通过新草稿生成新版本。

**产品确认点**：确认通过。

#### PUB-002 Visitor 授权查询

验收标准：

1. Visitor 仅凭有效 ShareGrant 建立访问会话。
2. 只能读取 PublicProjection，不能访问私人域。
3. Visitor 可通过文字、语音或数字人查询公开副本，但运行能力需单独放行。
4. Grant 撤销、过期或发布暂停后立即拒绝新访问。

**产品确认点**：确认通过。

### 8.10 兼容、通知与治理

#### KB-001 KBLite 兼容知识图谱

验收标准：

1. 兼容人物、地点、事件和事实的本地图谱。
2. 支持图谱查看、家庭 PDF、JSON 备份和治理操作。
3. KBLite 不能被描述为 V4 正式记忆权威。
4. 新 V4 Owner 回响链路不得混读 KBLite。

**产品确认点**：确认通过。

#### NOTI-001 通知、延迟回复与时光信

验收标准：

1. APNs 可传递已完成的延迟回复或任务状态。
2. 时光信拥有独立生命周期，不因 Legacy Archive 写入退役而丢失。
3. 通知只包含最小必要信息，打开后再鉴权读取内容。
4. 当前入口和 Worker 均按服务端策略显示。

**产品确认点**：时光信和延迟回复暂时关闭。

#### OPS-001 运行治理

验收标准：

1. 服务端是功能资格的唯一权威，客户端不能自行加入试点。
2. Release Policy 支持版本、修订、TTL、紧急关闭和最小客户端版本。
3. 供应商能力、Worker、积压与死信状态进入 Runtime Capability。
4. 失效或过期策略必须失败关闭。
5. 登录测试账号不得自动获得产品功能。

#### SEC-001 权限与隐私隔离

验收标准：

1. 每个请求绑定认证主体、Vault、Session 和 Authority Epoch。
2. Owner、Family、Visitor 的权限分别校验，关系不等于数据访问权。
3. 私人域、发布域和运行时域隔离，禁止反向写回。
4. 敏感接口使用幂等命令、版本检查和审计回执。
5. 账户切换、撤销、注销后旧异步结果不得写入新账户。

**产品确认点**：确认通过。

## 9. 核心业务流程

### 9.1 文字记忆

Owner 输入文字 → 创建 Source → 异步整理 Candidate → “待确认记忆” → 接受/纠正/拒绝 → MemoryVersion → Projection → SearchDocument → 回响使用。

### 9.2 Live 会话记忆

用户开启麦克风 → 保持 Live 会话 → 用户关闭或 60 秒无输入 → 保存转写 → DeepSeek 整理 → 生成候选 → 待确认 → 用户确认 → 正式记忆。

### 9.3 回响问答

用户问题 → 身份与安全校验 → 构建有权访问的记忆上下文 → DeepSeek 编排 → 返回文字、引用和 grounding 状态 → 使用实时语音播放 → 无记忆时转访谈或家庭贡献。

### 9.4 家庭贡献

Owner 授权 Family → Family 提交文字/图片 → Owner 审核 → 接受后形成 Source → V4 整理和待确认 → 正式记忆。

### 9.5 数据注销

用户二次确认 → 立即撤销会话与访问 → 30 日恢复窗口 → 到期分模块清理 → 记录内部/供应商回执 → 仅在全部完成时显示最终完成。

## 10. 非功能要求

| 类别 | 产品要求 |
|---|---|
| 性能 | 普通页面操作应即时反馈；后端异步整理显示进度；Live 首包和轮次延迟需单独监控 |
| 可用性 | DeepSeek、火山、腾讯数字人不可用时保留文字或无人格降级路径 |
| 一致性 | Source、Candidate、MemoryVersion、Projection 使用版本和哈希防止陈旧写入 |
| 安全 | 私人媒体不暴露对象 Key；供应商密钥仅后端保存；接口 no-store |
| 隐私 | AI 回复、数字人和声音明确披露；第三方处理需明确授权 |
| 可追溯 | 正式记忆可追溯到来源、用户决策和版本 |
| 可运营 | Feature、Provider、Worker 均可服务端关闭；失败原因可观测 |
| 无障碍 | 关键按钮有可理解标签，错误不只通过颜色表达 |

## 11. 当前代码明确未完成或未全量开放

1. Owner V4 Echo 当前未按问题相关性使用 SearchDocument 排序。
2. 家人身份回响尚未统一到 Owner V4 权威上下文。       **产品确认点**：全量开放。
3. V4 grounded 判定需补齐 ownerTruthMemoryProjection 引用来源。
4. 当前没有“全部正式记忆”独立总览，只能通过审核记录间接查看。       **产品确认点**：需要有入口可以查看全文，并支持可编辑。可编辑仅限于owner，编辑完成后需要二次确认修改，如此时程序关闭并为二次确认修改，可以视为二次确认取消。
5. App 尚未实现发布草稿的创建、编辑和二次确认，只能读取既有发布并在受控条件下撤回。**产品确认点**：需要具备。
6. 多媒体中，文档和视频的内容理解尚未完整落入三维候选链路。**产品确认点**：需要具备。
7. 家人克隆声音在 Echo 选择逻辑中仍被禁止。
8. Digital Human、Voice Clone、发布/Visitor 均依赖服务端和供应商，不能仅凭页面代码判定已上线。
9. KBLite、旧 Archive 和 MemoirService 属于兼容路径，不能继续扩张为第二套事实权威。
10. 发布和 Visitor 为 M2 QA/封闭试点。**产品确认点**：不存在M1、M2、M3和M4，需要全部开放功能。
11. 医生联系、关系解除等页面文案明确尚未开放。
