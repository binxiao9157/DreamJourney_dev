# Round 2A 产品定位、阶段范围与指标收敛方案

## Problem Definition

当前资料把多个价值主张和成熟度差异极大的能力同时列为 P0，工程则已在家庭、关怀、时间信件、声音复刻和数字人上投入大量实现，却仍缺少 Source、Candidate、Canonical Memory、强身份和可引用本人问答的产品权威闭环。需要重新从用户结果出发定义产品主线与阶段边界。

## Proposed Solution

1. 以 Owner 的私人记忆建设与可信调用作为近期产品主线，Publication/Visitor、Voice/Digital Human 和家庭类能力分别设为独立扩展轨道。
2. 定义核心目标用户和最多三个 JTBD，用可观察行为描述，不使用“认知平台”等不可验收抽象词作为 MVP 目标。
3. 把需求重排为 Stage 0 安全止损、Stage 1 Owner Truth Loop、Stage 2 摄入与质量、Stage 3 受控发布、Voice Beta、Stage 4 认知增强/未来扩展。
4. 保留现有“记忆档案 / 回响 / 我的”三 Tab 作为近期兼容 IA；目标概念通过页内入口和渐进迁移验证，不做一次性导航重构。
5. 定义一项北极星候选指标和三项以内结果指标，给出事件定义、合格阈值、去重、反刷和排除测试数据规则。
6. 将产品定位、阶段范围与指标写入 Product Spec V4 的对应章节，并把未决选择登记到产品决策登记册。

## Acceptance Criteria

- 有且只有一个近期产品定位，明确服务对象、用户结果和控制边界。
- Owner 核心闭环不依赖 Voice、Digital Human、Publication、Visitor、Family、Care 或 TimeLetter。
- 最多三个核心 JTBD 可由现有或计划中的产品事件验证。
- 36 条 FR 均有阶段归属；P0 不再等同于“全部并行开发”。
- 每个扩展轨道都有进入条件、退出门和不阻塞项。
- 北极星指标与结果指标都有计算窗口、合格事件和反作弊规则。
- 现有三 Tab 到目标概念有兼容映射和触发重构的证据门。

## Verification Plan

1. 对照 36 条 FR 检查阶段覆盖和依赖方向。
2. 对照当前 iOS 默认 feature flags 检查公开范围漂移。
3. 用三个 Owner 用户旅程验证定位、JTBD 与指标能形成闭环。
4. 由产品价值独立审查挑战范围和北极星，吸收或记录异议。
5. 运行 Product V4 文档检查与 `git diff --check`。

## Risks

- 将推荐定位误写成用户已确认决定。
- 为降低范围而丢弃已实现模块的数据兼容与未来价值。
- 指标只统计创建数量，诱导低质量记忆或 AI 自动灌入。
- 在没有用户验证前替换三 Tab，造成 UI 返工。

## Assumptions

- 私人记忆建设和本人可信问答是所有后续扩展的共同前置。
- 已实现的未来模块可以保留、隐藏和维护，但不自动进入近期公开范围。
- 产品可以先采用推荐口径作为计划基线，重大范围仍在决策登记册中保留确认状态。
