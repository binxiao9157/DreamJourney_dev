# Round 2D：Product Spec V4 集成与独立复审

## Problem

产品定位、领域模型和决策登记只有被整合成单一规范并通过反向审查，才能替代零散历史文档。需要产出 Product Spec V4 初稿、建立可读与机器可检的交叉引用，并从产品价值、隐私伦理、工程迁移、成本和外部依赖角度消除内部矛盾。

## Success Criteria

- 形成 `DreamJourney_V4_产品定义与目标架构_Product_Spec_V4.0.md` 初稿，覆盖文档控制、定位、用户/JTBD、指标、阶段闭环、角色权限、领域模型、IA、功能范围、AI 行为、隐私安全、供应商边界、运维和开放决策。
- Product Spec 中规范性结论标记为事实、已确认决策、推荐方案、外部依赖或待决策。
- 36 条 FR 均映射到 V4 阶段、领域与验收边界；21 个冲突均链接到决策登记册。
- 至少完成两类独立复审，所有高风险异议被修正或进入决策登记册。
- 对源 PRD、Blueprint 和分析底稿增加生命周期标识和 V4 引用，不删除历史证据。
- 新增静态检查，覆盖术语、状态、FR、冲突 ID、内部链接和禁用过度承诺措辞。
- `git diff --check`、Product V4 文档检查与 Closure ledger 检查通过。
- 该问题属于 T006，因为它负责把前序收敛结果变成唯一可执行产品规范。
