# Round 1：来源、需求与工程事实基线

## Problem

输入资料存在版本、范围和权威性差异，现有状态文档也可能落后于当前源码。必须先建立可追溯事实基线，才能避免后续产品与架构结论建立在过时假设上。

## Success Criteria

- 四份产品附件、Hermes/AOS 资料、既有 canonical docs 均完成来源分级。
- 最新 PRD 的 P0/P1 requirement ID 全部进入覆盖矩阵。
- iOS/后端关键能力按真实源码、测试和部署证据标为 ready/backend-ready/mock-hidden/missing/external。
- 文档冲突、旧结论失效和无源码支撑的推断形成显式清单。
- 产出 `DreamJourney_V4_当前实现证据矩阵_V1.0.md` 初稿。
