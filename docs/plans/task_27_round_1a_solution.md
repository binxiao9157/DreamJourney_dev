# 建立来源登记表和冲突清单

## Problem Definition

输入中既有产品评审稿，也有架构建议、静态分析和不完整源码。若不区分来源类型，后续会把推测的 AOS 能力或 Blueprint 方向误写成当前工程事实。

## Proposed Solution

逐份登记来源、日期、作者定位、可验证范围、依赖和权威等级；对 Hermes/AOS 只引用本地可见源码，缺失模块明确标为不可验证；对四份产品附件按术语、MVP 范围、角色、领域边界和阶段顺序做冲突表，并给每项冲突设置 fail-closed 默认处理和决策入口。

## Acceptance Criteria

- 输入来源无遗漏，来源等级使用统一枚举。
- 每个重要结论区分事实、文档主张和推断。
- 冲突清单覆盖 MVP 范围、IA、Domain、公开域、Family/Care/TimeLetter、声音和数字人。
- 不完整 AOS 模块不被标成可复用生产组件。

## Verification Plan

使用文件清单、标题和源码引用交叉检查；由独立 agent 复核冲突遗漏；所有本地链接必须存在。

## Risks

- 文档未包含作者审批状态，只能按内容和用户明确决策评估权威性。

## Assumptions

- 2026-07-11 PRD 为评审稿，不等于已经批准的发布范围。
