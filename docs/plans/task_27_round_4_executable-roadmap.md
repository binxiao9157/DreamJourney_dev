# Round 4：可执行开发路线与验收门

## Problem

产品和架构文档若不能拆成有依赖、有代码范围、有验证和部署边界的小闭环，就无法持续指导当前双仓开发。

## Success Criteria

- 路线按 P0/P1/P2、依赖关系和用户价值排序。
- 每个任务包含产品目的、代码范围、后端合同、迁移、flag、测试、部署、回滚和完成定义。
- 区分非真机、真机、真实 provider、生产部署和产品决策门。
- P0 不混入后置能力或无指标基础设施。
- 产出 `2026-07-12-dreamjourney-v4-executable-development-roadmap.md`。
