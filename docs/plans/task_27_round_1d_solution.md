# 合并 36 项 FR 的双端成熟度与下一动作

## Problem Definition

iOS 和后端矩阵按能力域描述，但产品执行需要逐个 requirement 判断。若不建立唯一映射，同一能力会被多个历史任务重复建设，或者合同壳层被误报为 P0 完成。

## Proposed Solution

从 PRD 机器提取全部 `FR-*`，为每项填写 iOS、后端、外部验收、综合成熟度、主要证据/缺口和推荐阶段。新增静态检查脚本，确保 PRD 与矩阵 ID 集合完全一致、无重复、无 `待审计`，并限制成熟度枚举。

## Acceptance Criteria

- 36 个 FR 唯一覆盖且无遗漏。
- 每项分别描述 iOS、后端和外部验收状态。
- 综合结论不高于最弱的业务闭环环节。
- 每项有推荐阶段或产品决策门。
- 静态覆盖检查可重复运行。

## Verification Plan

脚本解析 PRD 和矩阵表；比较集合、重复 ID、占位状态和枚举；主 agent抽查每个产品域至少一项源码证据。

## Risks

- PRD 自身 P0 过载，矩阵保留原优先级但路线图会重新按依赖和价值排序。

## Assumptions

- Round 1B/1C 的成熟度结论作为本任务输入。
