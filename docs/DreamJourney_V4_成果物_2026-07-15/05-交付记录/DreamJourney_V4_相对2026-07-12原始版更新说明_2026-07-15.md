## 2. 一页结论

2026-07-12 原始版是一份 **架构已评审、但大量产品选择仍待确认** 的建议性基线；2026-07-15 当前版已经把独立方案评审中的产品回复同步为 **产品选择基线**，并补齐人物记忆本体、纪念人物、查询 DFX 和初创团队轻量迁移设计。

最重要的变化不是技术拓扑重做，而是以下五点：

1. **产品验证改为三级**：Closed Pilot 先验证 Owner 文字记忆闭环；Product MVP 再加入家庭切换/贡献、受控 Publication/Visitor 和 Voice Clone；Beta Extension 承载 Digital Human、非必要媒体和后续能力。Family、声音、真机或法律延期不再阻塞核心价值验证。
2. **Product MVP 范围扩大并固定**：从 Owner 私人记忆与文字问答优先，调整为手机号身份、本人/纪念人物档案、家庭切换与贡献、文字问答、家庭受控 Publication/Visitor、Voice Clone、删除与权利回执共同组成 Product MVP；Digital Human 为受控 Beta Extension，Care/TimeLetter 后置。
3. **人物数字化数据模型被细化**：不再只使用通用 MemoryVersion，而是增加记忆类型、陈述视角、认知状态、类型化内容 Schema、记忆关系、PersonaProjection 与 EmbodimentProfile 的分层合同。
4. **逝者纪念场景被正式建模**：逝者不是登录账号主体；由在世且经核验的纪念账户主控人管理 MemorialVault 和 RepresentedPersona，家庭成员按来源贡献，Voice/Portrait/Digital Human 按用途另行授权和验收。
5. **重型迁移方案被分层**：百级用户阶段采用 L0-L3 Startup Lean Profile；C00-C11 完整组合迁移保留为规模、客户端兼容或运营条件触发后的升级目标。

当前版仍然是 `RELEASE_NO_GO`。产品确认只允许进入研发，不代表 115 个 Work Item 已实现，也不关闭法律、供应商、生产、真机、性能和发布审批门。

### 4.2 角色模型细化

当前版把原来的泛化 Owner/Family/Visitor 关系细化为：

- `Self Owner`：本人档案控制者；
- `Memorial Account Controller`：经强身份、死亡事实和近亲属关系核验的纪念账户主控人；
- `Represented Persona`：被纪念的人物，不是登录 principal，也不能被系统伪装为亲自同意；
- `Family Contributor`：按来源提交材料和个人陈述，不能直接把自己的观点写成逝者第一人称事实；
- `Visitor`：只在独立、可过期、可撤回的授权上下文中查询 PublicationVersion；
- `Operator/Admin`：默认不可访问私人正文，Admin break-glass 需要工单、短时、最小字段和双人批准。

这解决了“谁登录、谁控制档案、资料描述的是谁、谁能贡献、谁能查询”混为一个 Owner 字段的问题。

## 5. 人物记忆数据结构变化

### 5.1 原始版的不足

原始版已经定义 Source、Candidate、Decision、MemoryVersion、Projection 和 Citation，但人物经验、知识、情感、关系、性格等维度仍主要依赖通用内容载荷，缺少可执行的分类和约束，研发可能退化为“每人一个大 JSON”或自由 JSONB。

### 5.2 当前版新增的类型化合同

Product Spec 新增 `24.4A 人物记忆本体与类型化内容合同`，采用共同 Authority 主干和三个正交维度：

1. `MemoryKind`：内容属于经验、知识、情感、技能、关系、偏好、习惯、价值观、决策、目标或自我叙事等哪一类；
2. `PerspectiveType`：本人陈述、家庭成员陈述、第三方材料、系统观察或 AI 推断等来源视角；
3. `EpistemicStatus`：观察到、候选、已确认、被拒绝、被取代或存在争议等认知状态。

首批冻结 `experience / knowledge / emotion` 三类核心 Schema，其余维度进入同一 Schema Registry 演进。所有 MemoryVersion 使用统一 Envelope，具体内容按版本化 typed content schema 校验，并通过 `memory_relations` 表达人物、事件、时间、地点、知识和关系之间的连接。

### 5.3 人格、知识与表达层不再混存

当前版明确分离：

- `MemoryVersion`：带来源、视角和状态的记忆事实或陈述；
- `PersonaProjection`：从有效记忆投影出的人格、表达习惯和偏好，不是独立事实 Authority；
- `EmbodimentProfile`：声音、肖像、数字人形象和供应商资产；
- `Conversation/Answer`：运行时问答，不自动反向写成正式记忆。

个人问答中的新材料先形成 Candidate，再在约 5 至 10 轮或退出页面前批量确认；AI 回复、Visitor 问题和未确认推断不能自动成为人物事实。

## 6. 纪念人物与家庭共建变化

Product Spec 新增 `12.7`、`16.6`、`17.4` 和 `24.4B` 等纪念场景合同，核心变化为：

1. 逝者不注册为可登录、同意或签署条款的账号；
2. 在世主控人经身份、死亡事实和近亲属关系核验后创建 `MemorialVault + RepresentedPersona`；
3. 家庭成员分别提交 Source/Candidate，并保留“谁在何时基于什么材料作出何种陈述”；
4. 主控人拥有产品内日常管理权，但不能排除其他依法有权近亲属的异议、未成年人保护、第三方权利或平台法定义务；
5. 争议、撤权和有效 RightsRequest 可触发 scope hold、Publication 暂停和后续重审；
6. Voice、Portrait 和 Digital Human 必须分别绑定用途授权、来源、AI 标识、暂停/删除和 Provider 回执，不能由“建立纪念档案”自动推导为可用。

因此，当前版支持产品方向上的家庭共建，但没有把“掌握账号”写成无限权利，也没有把用户协议勾选当成法律免责。

## 7. Publication、Visitor 与授权上下文变化

原始版把 Publication/Visitor 作为后续阶段；当前版将家庭受控访问提升为 MVP-P，并固定以下边界：

- 私人 Source/Memory 不直接暴露给 Visitor；
- Owner/Controller 主动生成独立、脱敏、钉住 MemoryVersion 的 `PublicationVersion`；
- 每次访问必须携带独立的 `ShareGrant/授权上下文`，包含访问者、目标人物、用途、范围、有效期和撤回状态；
- Visitor 默认 TTL 为 7 天，主控人默认只能看授权使用统计和安全事件，不能看问题正文；
- Source 删除、Memory 修正、第三方异议或授权过期时，依赖 Publication 先暂停，再异步清理索引和对象；
- 匿名公共索引仍不进入首版。

## 8. 查询链路与后端 DFX 变化

### 8.1 检索链路被明确

当前版把问答检索细化为：

`问题预处理 -> QueryPlan -> 统一 Projection 混合检索 -> 候选 MemoryVersion -> memory_relations 扩展 -> 回溯 Source/MemoryVersion -> 权限再次校验与重排 -> Context Packet -> Answer + Citation`

这使多类 Memory 和多张关系表可以通过统一 Projection 检索，再回到 Authority 对象核验，不需要把所有人物信息压进一个 JSON，也不允许向量库或图数据库成为事实权威。

### 8.2 新增完整 DFX 合同

Product Spec 新增 `18.2A Projection / Retrieval 后端 DFX 合同`，先不计 ASR/TTS/Voice Clone/Digital Human 等第三方执行时间，覆盖：

- 基准负载：10 QPS 连续 30 分钟、1 秒内 100 并发突发；
- 稳态检索延迟：p95 不高于 600 ms、p99 不高于 1,000 ms；
- 突发检索延迟：p95 不高于 1,500 ms、p99 不高于 2,500 ms；
- Projection 新鲜度：p95 不高于 2 秒、p99 不高于 10 秒；
- Context Packet 上限 256 KB；
- 跨 Vault 泄漏、越权候选、已删除或撤权 Source、错误 Citation、关系重复/丢失必须为 0；
- 每个阶段独立上报延迟、候选数、裁剪、超时、取消、重试、连接池、锁和 Projection lag；
- 压测报告必须携带 build、环境、区域、规格、负载、样本、窗口、分母、冷启动和 artifact hash。

这些是研发与验收基线，不是当前已经取得的性能实测结果。

## 11. Startup Lean Profile 变化

当前版新增适合初创团队和百级用户的四阶段执行档位：

1. `L0`：资产盘点、备份、隔离恢复和回滚前置；
2. `L1`：离线迁移演练、数据校验和可重复执行；
3. `L2`：提前通知维护窗，冻结写入后完成切换和核验；
4. `L3`：切换后观察 24 至 72 小时，再决定退役旧路径。

完整 C00-C11 组合体系没有删除，而是在出现以下条件时启用：不能强制客户端升级、不能接受维护窗、多版本长期并存、迁移数据或流量显著增长、供应商/跨地域复杂度上升，或需要持续无停机切换。

轻量化没有取消以下底线：Vault 隔离、Source 引用、用途授权、访问撤回、删除回执、备份恢复、Provider fail-closed 和单一数据 Authority。

## 13. 未变化的架构主干

以下核心原则从原始版延续至当前版，没有被产品回复推翻：

- iOS 只持有用户级 Session，不持有 system token 或长期 Provider credential；
- HTTPS Edge 承担 TLS、Body Limit 和限流；
- DreamJourney API 采用 typed `/v2` 并保留受控 legacy facade；
- 后端仍以模块化单体、Postgres、私有对象存储和独立 Worker 为近期目标；
- 外部 AI、ASR/TTS/Voice Clone、APNs 和 Digital Human 通过 Provider Adapter/Port 隔离；
- Source -> Candidate -> Decision -> MemoryVersion 是事实形成主线；
- Projection、缓存、索引、向量和图结构均不是事实 Authority；
- 删除、撤回和供应商副作用必须通过异步 Job、Receipt 和 Reconcile 闭环；
- 公开/家庭查询只能读取独立 PublicationVersion，不能反向暴露私人域。

## 14. 当前仍不能声称完成的事项

1. 115 个 Work Item 没有因为文档更新而变成已实现；
2. Closed Pilot 仍需自身强身份、隔离、来源、纠正、删除和受控cohort证据，不能因范围变轻而直接开放；
3. Family、Publication/Visitor、Voice Clone 虽进入Product MVP，但在Gate关闭前仍必须默认关闭；
4. Digital Human和非必要媒体仍是受控Beta Extension，不能用Voice Product MVP的证据替代；
5. 7 项 `EXTERNAL_REQUIRED` 仍缺法律、安全、地域、供应商或真实环境证据；
6. Projection/Retrieval DFX 没有生产等价压测、金标质量集、恢复和故障演练结果；
7. 原始 PRD、Backend 源码和历史绝对证据路径不在成果包内，相关严格检查需要回冻结仓库重跑；
8. 中国首发法律文本、未成年人/第三方/逝者 Voice-DH、Provider 禁训练/留存/删除以及权利请求流程仍需专项审查；
9. 当前结论仍为 `IMPLEMENTATION_UNVERIFIED / RELEASE_NO_GO`。
